## 2. 預設 `--direct`

### 2.1 何時使用

`[tool.atc-testkit]` 沒有 `selector` key 時，`touched` 以預設 import edge 取代 fallback。宣告了 `selector` 的專案照舊：selector 優先，失敗時仍是現行的 changed test files（§ 8 D1）。使用預設時，在 `DECLARED` 行與 `RELATED` 行之前印一行 `SELECTOR default import edge`，讓 report 看得出 selection 來自哪裡。

### 2.2 路徑與基準

- changed paths 照舊相對於 repository top；先去掉 tree 的 prefix（`git rev-parse --show-prefix`，與現行 fallback 相同），不在 tree 內的 path 不產生 edge。
- 輸出的 test paths 相對於 tree，與 selector 的輸出、pytest 收到的 path 同一基準，所以 `with_declared` 與 step 6 不變。

### 2.3 changed path 對應到 module

一個 changed path 在以下任一 root 底下、副檔名是 `.py` 時，對應到一個 module name；`__init__.py` 對應到它的 package：

1. source roots：tree 的 `packages/*/src` 與 `src`（`pythonpath_directories`）；
2. pytest 的 `pythonpath`：tree 的 `pyproject.toml` `[tool.pytest.ini_options]` `pythonpath` 列出、存在於 tree 內的目錄；
3. test 目錄 helper：與某個 `test_*.py` 同目錄、且該目錄沒有 `__init__.py` 的 `.py` 檔，以 stem 為 module name，只對同目錄的 test files 有效（pytest 預設的 `prepend` import mode 把這個目錄放進 `sys.path`）。

一個 path 落在多個 root 時取最深的 root。已刪除的檔照樣對應（只看 path 字串），所以仍 import 它的 test 會被選入並失敗。`.py` 以外的檔沒有 import edge，由 declared dependents 處理。

（root 的範圍見 § 8 D2。）

### 2.4 掃描 test files

- 掃描 tree 下所有 `test_*.py`，不進入名稱以 `.` 或 `_` 開頭的目錄與 `node_modules`（`.venv`、`__pycache__` 因此排除），沒有深度限制。這是掃描自己的規則：step 5 的 locator 另外不進入 `src`、`tests`、`test` 並限三層，test files 正是在這些目錄裡，所以不沿用。
- 以 `ast.parse` 讀，不 import 任何專案碼；每個 `Import`、`ImportFrom` 都算，含函式內、`if TYPE_CHECKING:` 內的。
- 名稱：`import a.b.c` 給 `a`、`a.b`、`a.b.c`；`from a.b import c` 給 `a`、`a.b`、`a.b.c`（`c` 可能是 submodule，也可能是屬性，多一個名稱無害）。parent package 都算，因為 import `a.b.c` 會執行 `a/__init__.py` 與 `a/b/__init__.py`。
- 相對 import 在 test 檔所在目錄有 `__init__.py` 時，以它的 package 解析；否則忽略。
- 以 atc 自己的 interpreter parse，可能比專案的 Python 舊；parse 失敗的 test file 一律選入，並印 `UNPARSED <test path>`，寧多不漏。

### 2.5 package re-export

`from P import X`，P 是 changed module 所在的 package，而 `P/__init__.py` 以 `from .m import X`（或 `from P.m import X`）取得 `X`：這個 test 也得到 `P.m` 的 edge。只解析 `__init__.py` 這一跳，只認明寫的名稱（`import *` 不展開），不跟 `m` 再往下（§ 8 D3）。

### 2.6 選入規則

related 的 test paths 是：

1. changed paths 中存在於 tree 的 `test_*.py`（現行 fallback）；
2. 名稱集合（§ 2.4、§ 2.5）含某個 changed module name 的 test files；
3. changed `conftest.py`（§ 8 D4）：
   - tree 根目錄以下某個子目錄的 `conftest.py` 選入它所在的目錄，作為一個 test path；落在它底下的其他 path 拿掉，與 `dependents.merge` 的規則相同。
   - tree 根目錄的 `conftest.py` 作用於每個 test，所以 related run 改為 full suite：pytest 收到與 `--all` 相同、不帶 path 的參數，`RELATED` 行之前印 `FULL conftest.py at the tree root`，`RELATED` 的 `<k>` 寫 `all`。
   - 一個 `conftest.py` 以 `pytest_plugins` 或 import 載入的 tree 內 module（§ 2.3 對應得到的），改動時視同該 `conftest.py` 改動，只看這一跳。

   hami-quant-trading 在 main `9f118fae` 有兩個：根目錄的 `conftest.py`（只有 `pytest_plugins = ("atc_testkit.plugin", "tk_window_events", "tk_root_guard")`，後兩者是 `scripts/tests/` 的 module）與 `packages/trading-signals/tests/conftest.py`（252 行，選入該目錄的 32 個 test files）。改根目錄的 `conftest.py`、`scripts/tests/tk_window_events.py` 或 `tk_root_guard.py` 都會跑 full suite（285 個 test files）；根目錄的 `conftest.py` 自 2026-08-01 起至少改過 5 次。hami-quant 在 main `23195fa` 同樣有根目錄 `conftest.py`，另有 `packages/hami-quant-cli/tests/`、`packages/hami-quant-console/tests/` 兩個。

一條 edge、不取 closure：被選入的 test file 不再帶入 import 它的檔。之後 declared dependents 照 ATC-0084 加上。

### 2.7 實作位置

新 module `atc_testkit/import_edge.py`，公開 `direct(tree: Path, paths: Sequence[str]) -> list[str]`，純函式、只讀檔案系統；`testrun.touched` 在沒有 `selector` 時呼叫它。stage-time record、input evidence、`selector_record()` 都不變：selection 的結果仍只是 pytest 收到的 path 清單。

## 3. 與其他 selection 的關係

- **declared dependents**：不變，加在預設輸出之上；`DECLARED` 只印預設沒選到的。預設 edge 上線後，dependents 只需寫 import 以外的讀取（ATC-0084 § 5 的結論）。
- **mutant selection**：`selected_mutants` 經由 `touched` 自動得到預設 edge，沒有 selector 的專案的 mutant 不再需要手寫 `tests` 才能跑（§ 8 D5）。ATC-0084 § 3 的「mutant 不讀 declared dependents」不變。
- **verifier 與 pre-push gate**：不經過 `touched`，不變；它們的 targeted selection 仍是專案的 `select` 與 shared `classify`。

## 8. 要 Owner 裁決的事（Decisions for the Owner）

每項一個決定，建議的選項在前。

### D1 何時使用預設

- **A（建議）只在沒有 `selector` key 時**（§ 2.1）。改變：專案宣告的 selector 完全優先，符合 task scope；壞掉的 selector 仍默默退回 changed test files。
- **B 也在宣告的 selector 失敗或輸出無效時**，並印 `SELECTOR_FAILED <reason>, default import edge`。改變：壞掉的 selector 不再讓 related run 縮小；root 的 selector 出錯時，related run 換成不含字串 edge 的預設，行為與 verifier 的選法差得更遠。

### D2 module 對應的 root

- **A（建議）source roots、pytest `pythonpath`、test 目錄 helper 三者**（§ 2.3）。改變：hami-quant-trading 的 `scripts/*.py`（24 個 test files）與 `demo_sources_support.py`（34 個檔）改動時也選得到 import 它們的 test；要讀 `[tool.pytest.ini_options]`。
- **B 只有 `packages/*/src` 與 `src`**（task scope 的字面）。改變：實作最小；改 `scripts/` 或 test helper 時仍只跑 changed test files。

### D3 package re-export

- **A（建議）解析 `__init__.py` 一跳、只認明寫的名稱**（§ 2.5）。改變：`from hami_quant_trading_signals import SignalLedger` 這類 test 在 `ledger.py` 改動時選入；只多選真的用到該名稱的檔。
- **B 不解析。** 改變：只認 import 敘述寫出的 module；從 package root 取名稱的 test 漏選，要靠改 test 的 import 寫法或宣告補。
- **C import 一個 package 就得到 `__init__.py` import 的每個 submodule。** 改變：最貼近執行期實際載入的檔；任何 re-export 的 submodule 改動都帶上該 package 的所有 test，related run 接近 package 的全部 test。

### D4 changed `conftest.py`

- **A（建議）子目錄的選入它的目錄，根目錄的跑 full suite**（§ 2.6 第 3 條）。改變：fixture、hook 與 plugin 的改動一定跑到受它影響的 test；hami-quant-trading 改 `packages/trading-signals/tests/conftest.py` 跑該目錄的 32 個檔，改根目錄 `conftest.py` 或它載入的 `tk_window_events.py`、`tk_root_guard.py` 時 related run 就是 full suite（285 個檔），與 root `select_tests` 對 `conftest.py` 的規則相同。這類改動不常見，但 related run 在那時不再小。
- **B 只選用到它 fixture 的 test files。** 以 `ast` 取 conftest 定義的 fixture 名稱，比對 test 函式的參數名與 `usefixtures` 字串；有 `autouse` fixture 或 hook 的 conftest 仍選整個目錄，根目錄的仍是 full suite。改變：hami-quant-trading 的 signals conftest 只帶入真的用到其 fixture 的檔；根目錄 `conftest.py` 只有 `pytest_plugins`，對它沒有差別；fixture 經由其他 fixture 間接使用時要再解析一層，規則與測試都變多。
- **C 不選**（現況）。改變：related run 小；conftest 與它載入的 plugin 的錯誤只在 candidate 的 full suite 出現。

### D5 mutant selection 是否用預設

- **A（建議）用**（§ 3，`touched` 是同一個函式）。改變：沒有 selector 的專案的 mutant 自動得到 import 它的 test 作 judging test；reviewer 不必逐個寫 `tests`。
- **B 不用，mutant 保留現行 fallback。** 改變：`touched` 要分兩種呼叫；沒有 selector 的專案的 mutant 仍需手寫 `tests`。
