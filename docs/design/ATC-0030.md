# ATC-0030 design: the pre-lock layout's migration branches

Task: ATC-0030 (`.atc/tasks/ATC-0030.yaml`), base dd815c4. The record binds
this design: inventory first, the Owner rules which branches go, nothing under
`shared/governance/` changes, no version bump unless the Owner rules one.

## 1. The layout being retired

`atc` 0.1.0 pinned a project's governance in `.atc/governance.yaml` (YAML,
`managed-by: agent-traffic-control`, `source`, `revision`), wrote a policy
block between `<!-- atc:project-policy-reference begin/end -->` into the
project's `AGENTS.md`, and installed a `CLAUDE.md` that told the reader to
read `AGENTS.md`. Commit ef39a07, released in 0.2.0, replaced all three with
`.atc/atc.lock`, the pointer line and the `@AGENTS.md` import, and taught sync
to migrate the old files. The current version is 0.4.0.

### Sibling migrations of the same layout

The same 0.1.0-to-0.2.0 migration has two more branches, outside this task's
scope unless the Owner adds them:

- **Policy block in `AGENTS.md`**: `validate_workspace.LEGACY_POLICY_*` and
  the `validate` failure for it; `onboard_project.pointer_plan` replacing it;
  `link-skills.sh` replacing it; `check-skills.sh` reporting it stale; tests
  in `test_tooling.py` (around the "policy block is from an older release"
  assertion) and `test_shell_install.py`.
- **Old `CLAUDE.md`**: `onboard_project.LEGACY_CLAUDE_MD` and
  `link-skills.sh` `LEGACY_CLAUDE_SUM`, each replacing an exact copy of the
  old text with the import.

## 4. What the compatibility rule requires

`shared/conformance/CLI.md` § Versions and compatibility:

- A breaking change is a change to a CLI command, subcommand, option,
  positional, exit code, verdict token or `--json` field's presence or
  meaning; the task record schema; the `atc.lock` format; a governance
  contract; a conformance fixture. It lands only in a minor version and the
  release notes mark it BREAKING.
- The alias-for-one-minor rule covers renames of commands, subcommands and
  options only.
- `atc` reads the `atc.lock` and task records of the previous minor version,
  and `onboard --sync` migrates them.
- Release notes give every breaking change, deprecation and removal.

Applied here:

- `.atc/governance.yaml` is the 0.1.0 layout. The read window is the previous
  minor of 0.4.0, that is 0.3.x, whose layout is already `atc.lock`. Dropping
  the file falls outside the window, so no deprecation step is owed.
- No command, option, exit code, verdict token or `--json` field changes:
  `NO_GOVERNANCE_BINDING` stays, only its detail text drops the legacy name;
  an `onboard --json` plan for a project still holding the file shows a
  `collision` event where it showed an `update`, which is the existing meaning
  of those events. The record schema, the lock format, governance and the
  fixtures are untouched. The removal is not a breaking change by the list.
- It is a removal, so the next release's notes list it. Those notes come from
  the release commit's body plus the task records since the previous tag
  (`.github/workflows/validate.yml`, the notes step), so ATC-0030's record
  scope already carries it; the release commit body names it too.

## 5. Proposal

**Remove now** (one commit, tests and docs to the final state):

1. `task_records.bound_governance`: the fallback; with no lock it refuses
   `NO_GOVERNANCE_BINDING` with "`.atc/atc.lock` is missing; run atc onboard
   --sync". Its two fallback tests go; the unmarked-legacy refusal case goes
   (the plain "lock missing" case already covers it).
2. `validate_workspace.LEGACY_MANIFEST` and its special message: a leftover
   file becomes an ordinary stray ("not a file sync writes").
3. `onboard_project.legacy_manifest` and its two uses: a leftover file becomes
   an ordinary collision, and sync leaves `.atc/` alone. The migration test
   keeps the policy-block and `CLAUDE.md` parts and drops the pin file; the
   unmarked-collision test becomes a marked-file collision test.
4. `link-skills.sh`: the `LEGACY` variable, the stray-scan case, the lock
   rewrite condition and the deletion; the header comment. The shell test's
   migration case drops the pin file and asserts nothing about it; the
   collision case keeps `.atc/governance.yaml` as an ordinary stray.
5. `check-skills.sh`: the `stale` line. A leftover file is then not reported
   by `check-skills.sh` (it checks what sync owns, not strays), and
   `link-skills.sh` stops on it as a collision.
6. `docs/LAYOUT.md`: the sentence about the legacy file.

**Keep, or remove on the Owner's word**: the policy-block and old-`CLAUDE.md`
migrations (§ 2, sibling migrations). They are the same 0.1.0 layout, no
registered project needs them, and the same compatibility reading applies.
Removing them in this task widens its scope beyond the record; the
recommendation is to remove them here too, so the 0.1.0 layout leaves in one
change, with the record's scope amended by the Owner's ruling.

**Version**: no bump and no deprecation step. The removal goes into the next
release's notes through the record and the release commit body.
