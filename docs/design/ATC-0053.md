# ATC-0053 設計：hook 自己維護 table；`atc guard --install` 變成每台主機一次的步驟

範圍見 `.atc/tasks/ATC-0053.yaml`。Owner 11-16 的裁決：

- 這項改動在下一次發版之前落地，發版等它。
- 採用 ratchet（§ 5.2）。
- 「全部都做」：doctor 的版本落差判斷一併納入（§ 6.1）。

## 1. 現況與目標

`atc guard --install` 目前做兩件事：

- 寫 harness entries；
- 把 workspace policy、各 project policy 和 workspace map 組成 `~/.atc/enforcement/pretooluse.json`。

只要 table 的任何一個輸入變了，table 就過期：裝了新的 `atc`、policy 改了、`atc add`/`atc remove`。之後 `atc doctor` 會一直報 drift，直到 Owner 重跑。

目標是讓 `atc hook` 從經過 review 的輸入自己組 table，用 key 快取。`--install` 變成每台主機只跑一次的步驟：寫 harness entries，並寫入初始 baseline（§ 5.2）。之後的 `atc` 安裝、policy 改動、`atc add`，都不需要 Owner 再跑一次。

## 2. 輸入解析

一次組合（compose）讀進下列輸入，順序與今天的 `hook_table` 相同。

| # | 輸入 | 從哪裡讀 | 進 key 的形式 |
| --- | --- | --- | --- |
| 1 | workspace map | entry 的 `--workspace` 指定的檔案（§ 7） | 檔案 bytes 的 sha256 |
| 2 | workspace policy | 見下方 2a/2b | 2a：`[repo 路徑, main SHA]`；2b：檔案 bytes 的 sha256 |
| 3 | 每個已註冊 project 的 policy | map 裡 `projects.<name>.repo` 的 `refs/heads/main` | `[name, repo 路徑, main SHA]` |
| 4 | map 引用的環境變數 | `agent_write_roots` 裡出現的每個 `%VAR%`、`$VAR` | `{name: value}` |
| 5 | composer | 正在執行的 `atc` 本身的組合程式碼與 schemas | 檔案指紋（§ 3） |

home 目錄與 ATC home 不從環境變數讀，一律由 entry 的 `--home`、`--atc-home` 給定（§ 7；理由見 § 8 的 N1 那一列）。

**2a. governance checkout 主機**（例如本機，workspace 目錄本身就是 ATC repo）：workspace policy 從 content repository 的 `refs/heads/main` 讀。content repository 的規則與 sync 相同（`content.repository(root, fetch=False)`），只是 ATC home 改用 entry 的 `--atc-home`：

- 有 `governance_checkout` 時，用它；
- 否則用 `<atc-home>/content/<owner>/<repo>.git`。

workspace 目錄是 governance checkout、map 卻沒寫 `governance_checkout: .` 時，與 sync 一樣停在 `GOVERNANCE_CHECKOUT_UNSET`。本機目前的 `workspace.yaml` 就缺這一行，見 § 10。

**2b. 一般 consumer workspace**：workspace policy 是 sync 以 `create-only` 寫進 workspace 目錄的 `policies/hard-deny.yaml`（`atc-manifest.yaml` 的 `workspace-policy`）。它跟 map 一樣是機器本地、不在 Git 裡的檔案，所以：

- 檔案 bytes 的 hash 進 key；
- 檔案加進 table 的 `protected`（§ 3）。

**Policy 內容的讀法。**

- 依 key 裡的 SHA 讀，不讀 ref 名稱：每個 repo 一次 `git cat-file --batch`，輸入 `<sha>:policies/<kind>.yaml`。這樣 key 和內容之間沒有 TOCTOU。
- 每個 blob 先看 `--batch` 回報的大小，超過 256 KiB 就是 `POLICY_TOO_LARGE`，不讀內容。
- YAML 用一個 SafeLoader 子類別載入，它遇到 anchor 或 alias 事件就拒絕（`POLICY_INVALID: YAML aliases are not allowed`）。這樣解析時間與大小成正比，不會被 alias bomb 拖住。
- 內容在記憶體裡交給 `policies` 驗證：新增 `policies.load_texts({kind: text})`，`load(directory)` 改成呼叫它，schema 檢查和 contradiction 檢查都和今天一樣。
- 某個 project 的 main 上沒有 `hard-deny.yaml`：那個 project 不貢獻 policy 規則，但它的 state、worktrees 照樣進 table，與今天相同。

**Map 的讀法。** 組合時解析的 map bytes，就是拿去算 hash 的同一份：讀一次 bytes，先算 hash，再用 `yaml` 解析這份 bytes。map 同樣不接受 alias。

**不會進 table 的東西。**

- worktree 裡的編輯、canonical checkout 尚未 commit 的編輯：只讀 main 的 Git objects。
- topic branch 上的 commit：只認 `refs/heads/main`，不認 `HEAD`。

**Git 子行程。**

- 每個 git 呼叫都是 `git --no-replace-objects -C <repo> ...`，所以 `refs/replace/*` 不會被套用。
- 環境從零開始組，只留 `PATH`、`SYSTEMROOT`、`TEMP`/`TMP`，再設 `HOME`（取自 entry）、`GIT_CONFIG_NOSYSTEM=1`、`GIT_TERMINAL_PROMPT=0`。因此 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE`、`GIT_OBJECT_DIRECTORY`、`GIT_ALTERNATE_OBJECT_DIRECTORIES`、`GIT_COMMON_DIR`、`GIT_NAMESPACE`、`GIT_CONFIG_*`、`GIT_CONFIG_PARAMETERS`、`GIT_CONFIG_COUNT` 一律不會傳下去（governance `GIT_WORKFLOW.md` § Git environment in hooks and tests）。
- `cat-file` 與 `rev-parse` 不跑 hook，也不跑 fsmonitor。
- alternates（`objects/info/alternates`）只能多提供 object；object 以內容定址，所以它無法改變某個 SHA 的內容。hook 不擋它，`--reset` 會擋（§ 5.4）。

**命中路徑讀 main SHA 不開 git。** 依序讀：

1. `<gitdir>/refs/heads/main`（loose ref）；
2. 讀不到就找 `<gitdir>/packed-refs` 裡 `refs/heads/main` 那一行。

`<gitdir>` 是 repo 的 `.git` 目錄；bare cache 則是 repo 本身。只有遇到下列三種情況，才退回 `git --no-replace-objects rev-parse --verify -q refs/heads/main^{commit}`：

- `.git` 是一個 `gitdir:` 檔；
- `config` 宣告了 `extensions.refStorage`；
- ref 檔的內容是 symbolic ref。

兩種方法都讀不到 SHA 時，就是 `MAIN_UNREADABLE`。

## 3. 狀態檔：baseline、快取、鎖

全部放在 `<atc-home>/enforcement/`，這個目錄本來就在 `protected` 裡。每個 map 一組檔案，以 map 絕對路徑（long form、case-folded）的 sha256 前 16 個 hex 字元 `<m>` 命名：

| 檔案 | 內容 | 誰寫 |
| --- | --- | --- |
| `baseline-<m>.json` | `{"version": 2, "table": {...}, "inputs": {...}, "written_by": "install" \| "reset" \| "hook", "at": ...}`，也就是 ratchet 的狀態（effective table） | `--install`、`--reset`（Owner 的 terminal）；hook 只能寫 `baseline ⊕ fresh`（§ 5.2） |
| `table-<m>.json` | `{"version": 2, "key": {...}, "table": {...} \| null, "failure": {...} \| null, "atc": {"version", "commit"}}` | hook（命中快取） |
| `compose-<m>.lock` | 一個 byte 的鎖 | hook、`--install`、`--reset` |

`table` 的格式就是今天的 version 1 table，引擎直接讀它。

每個 map 各有一份，所以為另一個 map 組出來的東西永遠不會碰到真正 map 的那份。所有寫入都是先寫暫存檔，再 `os.replace`。

**Table 的 `protected`** 包含：

- 今天的項目：狀態檔目錄、引擎檔、tool 環境；
- 新增：map 檔；
- 新增：2b 的 workspace policy 檔；
- 新增：組合時正在執行的 `sys.prefix`，條件是它含有 uv 寫的 `uv-receipt.toml`。這一項取代 `uv tool dir` 子行程。

**Key** 是 § 2 表格最後一欄的各項，加上 `composer` 和 `format`，組成一個 JSON 物件，全部相等才算命中。

- `composer` 是一個 sha256，涵蓋正在執行的 `atc_cli/scripts/{generate_enforcement,policies,globs,shell_words,write_targets,pretooluse_hook}.py` 和 `atc_cli/schemas/hard-deny.schema.json` 的 `(相對路徑, size, mtime_ns)`。`uv tool install` 會換掉這些檔案，所以裝了新版本，key 就會變。key 不放版本字串，因為在 worktree 的開發環境裡，同一個版本號可能對應不同的程式碼。快取的 `atc` 欄位另外記錄組合當時的版本與 `direct_url.json` commit，只供回報用。
- `format` 是 table 格式的版本，現在是 2。

命中時，hook 從快取裡讀出 project 清單與環境變數名稱，再逐一讀 main SHA 與變數值。這樣做是安全的：map hash 沒變，代表兩份清單都沒變，所以命中路徑完全不必解析 YAML（hook 只能用標準函式庫）。

快取的 `failure` 只跟它自己的 `key` 綁在一起。寫 failure 時不動 baseline，`table` 欄位也不清掉別處的狀態。

## 4. 每次 tool call 的成本

以下是 11-16 在本機（Windows 11）實測的數字，每項取 15 次的中位數。已安裝的 0.6.0 還沒有 `atc hook`，所以基準是把各段分開量：

| 量測 | 中位數 |
| --- | --- |
| tool 環境的 python 空跑（`-c pass`） | 29 ms |
| 引擎直接跑（main 的 `pretooluse_hook.py` 加上現有的 table，一個 Bash payload） | 71 ms |
| `atc --version`（0.6.0 的 console entry） | 100 ms |
| 命中路徑原型：map sha256、5 個 repo 的 main ref、7 個 composer 檔的 stat | 0.95 ms（行程內） |
| 載入 table JSON（59 條規則） | 0.19 ms（行程內，與今天相同） |
| 未命中：`git show` ×20 + import yaml/jsonschema + 組合 | 668 ms（import 91、git 455、組合 51） |

結論：

- **命中時**，每次呼叫只多出約 1 ms。主要成本仍然是 `atc` 行程啟動，與今天相同。packed-refs 很大的 repo 每次都要掃一遍，成本仍可接受。
- **未命中時**，用每個 repo 一次 `cat-file --batch` 取代 20 次 `git show`，再加上組合子行程的啟動（§ 5.1，約 100 ms），預估約 400 ms。每次 key 改變，整台主機只付一次。最壞情況由 § 5.1 的總期限 6 s 封頂。

## 5. 組合、ratchet 與 fail closed

### 5.1 未命中時的流程與期限

harness 的 timeout 是 10 s。Codex 在 hook 逾時的情況下會讓 call 照常執行（ENFORCEMENT § PreToolUse hook「Failure」），所以 miss 路徑有一個**總期限 6 s**，從 hook 行程啟動開始算，等鎖和組合都算在內。

1. 在期限內反覆嘗試取得 `compose-<m>.lock`。到期還拿不到 → deny `COMPOSE_BUSY`。這個結果不寫進 failure，因為持有鎖的行程本身也受同一個期限約束。
2. 拿到鎖後重讀快取。別的行程已經寫好相同 key 的結果（table 或 failure）時，直接用它。
3. 讀 baseline。缺少 → deny `BASELINE_MISSING`；讀不出或格式不對 → deny `BASELINE_INVALID`。兩者都不寫 failure，修法是 Owner 跑 `atc guard --reset`（§ 5.3）。
4. 以 `subprocess.run([sys.executable, "-I", "-m", "atc_cli.compose", ...], timeout=剩餘期限)` 組 fresh table：
   - 子行程拿到的是 key（含各 SHA）、`--home`、`--atc-home`，以及 § 2 那份乾淨的 git 環境；
   - 它在 stdout 回傳 fresh table，或一則 failure；
   - 父行程是 hook 本身，只用標準函式庫。逾時就 kill 子行程，記為 `COMPOSE_TIMEOUT`。
5. 成功時，新的 baseline = baseline ⊕ fresh（§ 5.2）。先寫 baseline，再寫快取 `{key, table: 新 baseline}`。失敗（含 `COMPOSE_TIMEOUT`）時，只寫快取 `{key, failure}`，baseline 不動。
6. 放鎖。

鎖用 `msvcrt.locking`／`fcntl.flock` 鎖住鎖檔裡的一個 byte，持有者結束時 OS 會自動釋放，所以不會有殘留的鎖。

因為逾時會依 key 寫進 failure，同一個 key 之後的 call 會在第 2 步立刻 deny，不會每次都重組到逾時。輸入改變後 key 也會變，才會再試一次。

### 5.2 Ratchet：自動組合只會收緊（已裁決）

`⊕` 的定義：

- `commands`、`filesystem`、`worktrees`、`protected`：取聯集。去重的 key 沿用今天的做法：command 用條件 JSON，filesystem 用 `[glob, modes, scope]`。同一個 key 的 `reason`/`source` 以 fresh 為準。
- `write_roots` 是 allowlist，所以取交集：
  - fresh 的某個根，只有位在 baseline 某個根之內時才保留；
  - baseline 的某個根，只有位在 fresh 某個根之內時才保留（`within` 用 `shell_words.within`）。

baseline 不存在時，hook 不會自己開始一份（§ 5.1 第 3 步）。只有 `--install` 和 `--reset` 會在 Owner 的 terminal 裡建立 baseline：

- `--install`：baseline = 舊 baseline（若有）⊕ fresh ⊕ legacy `pretooluse.json`（若有）。兩者都沒有時，baseline 就是 fresh 本身，不和空集合取交集，否則 `write_roots` 會變成空的。
- `--reset`：baseline = fresh（§ 5.4）。

只出現在 baseline、不在 fresh 裡的項目算是 `retained`：保留下來的規則，以及 map 有、但尚未生效的 write roots。doctor 和 guard 會回報它（§ 6）。

這兩條路都不能讓 table 變鬆：

- 輸入的改變（本地 main 的移動、map 的改變）只會走 `⊕`；
- 組合失敗、快取壞掉，都不動 baseline；
- baseline 被刪掉或弄壞，只會 deny，不會從 fresh 重新開始。

放鬆只有一條路：Owner 跑 `--reset`。

### 5.3 Fail closed 與訊息

組合失敗時，hook 一律 deny 每一個 call（範圍要求），Claude 和 Codex 都一樣。每則訊息都以 `Refused: the PreToolUse hook cannot compose its table:` 開頭，結尾都是 `Every session is blocked until this is fixed; the Owner runs atc doctor from their own terminal for the cause.`

| 原因 | token | 訊息重點 | 寫進 failure | 修法 |
| --- | --- | --- | --- | --- |
| map 不存在或讀不到 | `WORKSPACE_MISSING` | `<map> cannot be read (<err>)` | 是 | Owner 恢復 map |
| map 不是合法 YAML 或欄位錯誤 | `WORKSPACE_INVALID` | `<map>: <err>` | 是 | Owner 修正 map |
| policy 不合 schema、互相矛盾或含 alias | `POLICY_INVALID` | `<label> <repo>@<sha>: <problem>`，每個 problem 一行；另附一句 `if atc doctor reports the installed atc older than main, installing the latest release may be the fix` | 是 | 在 topic 修 policy，經 review 整合進 main；若這個 main 不是 review 過的那一個，Owner 把它還原成 upstream |
| policy blob 太大 | `POLICY_TOO_LARGE` | `<label> <repo>@<sha>: policies/<kind>.yaml is <n> bytes, over 262144` | 是 | 同上 |
| repo 沒有 main 或讀不到 | `MAIN_UNREADABLE` | `<label>: <repo> has no refs/heads/main (<err>)` | 是 | Owner 修 repo，或 `atc remove` |
| governance checkout 沒在 map 宣告 | `GOVERNANCE_CHECKOUT_UNSET` | 同 sync 的 detail | 是 | 在 map 加上 `governance_checkout: .` |
| 組合超過期限 | `COMPOSE_TIMEOUT` | `composing <inputs as label@sha7> took longer than 6 s` | 是 | 同 `POLICY_INVALID` |
| 等鎖超過期限 | `COMPOSE_BUSY` | `another process is composing` | 否 | 重試這個 call |
| baseline 缺少 | `BASELINE_MISSING` | `<path> is missing` | 否 | Owner 跑 `atc guard --reset` |
| baseline 壞掉 | `BASELINE_INVALID` | `<path>: <err>` | 否 | 同上 |
| 快取讀不到、不是合法 JSON 或 key 不符 | （不算失敗） | 當作未命中 | — | — |
| 引擎本身出錯 | 今天的訊息 | `REPAIR` 改為 `atc doctor` | 否 | Owner 跑 `atc doctor` |

agent 在 deny 期間仍可以用 Read/Grep（不在 matcher 裡）去看原因，並把訊息轉給 Owner。

### 5.4 `atc guard --reset`（Owner 專用，唯一的放鬆路徑）

`--reset` 在 Owner 的 terminal 裡當場組合，不交給下一次 hook。步驟如下，任一步拒絕都不改任何檔案：

1. **entries 必須是最新的。** entries 是 `ENTRY_MISSING` 或 `ENTRY_OUTDATED` 時，以同樣的 token 拒絕，修法是先跑 `--install`。原因：舊的 static entry 少了 legacy 檔，就會擋住全部 call。
2. **檢查每個 Git 輸入。** 有 `refs/replace/*`（`git for-each-ref refs/replace`）→ `REPLACE_REFS_PRESENT`；有 `objects/info/alternates` → `ALTERNATES_PRESENT`。兩者都拒絕，並列出 repo。
3. **與 upstream 比對。** 每個 Git 輸入印一行 `<label> <repo>@<sha>`，接著和它的 upstream（`refs/remotes/origin/main`，不 fetch）比對：
   - main 不是 upstream 的後代（兩者分叉，或 main 被改寫過）→ `MAIN_DIVERGED`，拒絕；
   - main 領先 upstream → 印出領先的 commit 數，並逐一列出改到 `policies/` 的 commit（`<sha7> <subject>`）；
   - 沒有 upstream ref → 在該行標示 `no upstream to compare`。

   這一步不 fetch。agent 也能用 `update-ref` 改 `refs/remotes/origin/main`，所以這裡的比對只是參考資訊。真正讓 Owner 知道自己放鬆了什麼的，是第 5 步列出的、會被丟掉的規則。
4. **在 § 5.1 的子行程裡組 fresh table**（這裡沒有 6 s 期限，只用 60 s 的保護上限）。
5. **列出 baseline → fresh 會丟掉什麼**：每一條規則（id、source）、每一個 write root；也列出 fresh 新增的 write roots。baseline 缺少或壞掉時，改拿快取 `table-<m>.json` 的 table 比對；快取也沒有，就拿 legacy `pretooluse.json` 比對。這一節的標題會寫明 `no baseline: compared with <the cache|the legacy table|nothing>`，讓 Owner 知道比對的對象不是 baseline。
6. **確認。** 問 `reset the table to these inputs? [y/N]`（與 `atc remove` 同一種確認方式）。回答不是 y 就以 `DECLINED` 結束。
7. **在鎖底下寫入。** 以原子寫入把 baseline 換成 fresh（`written_by: reset`、`inputs`），刪掉這個 map 的快取，也刪掉 legacy `pretooluse.json`。

有 `--json` 時印出同樣的內容，但只有加上 `--yes` 才會寫入。`--yes` 本身也在 hard-deny 範圍內，因為整個 `--reset` 都是。

`--install` 也在 Owner 的 terminal 裡組合，並執行第 2、3 步。它不丟任何規則，所以不需要第 5、6 步。寫入 baseline 之後，它也會刪掉這個 map 的快取 `table-<m>.json`，因為舊快取的 table 可能比新 baseline 寬鬆。

**Owner 指令用哪個 home。** `--install` 用它自己解析出的 home（`Path.home()`）和 ATC home（`ATC_HOME`，否則 `<home>/.atc`），寫進 baseline，也寫進 entry 的 `--home`、`--atc-home`。`--reset` 和 check 也用同樣方式解析。entry 上的兩個值和這裡解析的不一致時，算 `ENTRY_OUTDATED`，所以 `--reset` 會拒絕。這樣 Owner 指令寫出的 baseline，一定就是 hook 讀的那一份。

**組合子行程的期限**（hook 與 Owner 指令相同）：

- 用 `Popen` 啟動，stdout 與 stderr 寫到暫存檔，不用 pipe，再以 `wait(timeout=剩餘期限)` 等它結束；
- 逾時時，先 kill 整個行程樹（Windows 用 `taskkill /T /F`，POSIX 用 process group），再做一次有上限的 `wait`；
- 子行程呼叫 git 時，stdout 與 stderr 都由子行程自己 capture。

這樣孫行程就算繼承了 handle，也拖不住父行程。

## 6. `atc doctor` 與 `atc guard`（check）回報什麼

兩者都在記憶體裡組合（用 § 5.1 的子行程，只有 60 s 的保護上限），絕不寫狀態檔；doctor「不改任何東西」。各列一行：

| 檢查 | READY | 其他狀態 |
| --- | --- | --- |
| `pretooluse entries` | 兩個 harness 的 entry 都恰好是 rendered group，帶這個 map 的 `--workspace` 以及正確的 `--home`、`--atc-home` | `ERROR ENTRY_MISSING`／`ENTRY_OUTDATED` → the Owner runs atc guard --install |
| `pretooluse baseline` | `written by <install\|reset\|hook> at <time>` | `ERROR BASELINE_MISSING`／`BASELINE_INVALID` → the Owner runs atc guard --reset |
| `pretooluse table` | `composes; <n> rules; inputs <label>@<sha7>...`，再加上 `cached` 或 `recomposes on the next call` | `ERROR <token>: <detail>`，與 § 5.3 相同並附修法；快取裡有同 key 的 failure 時一併列出 |
| `pretooluse retained` | 沒有 retained 時不列 | `WARN <n> rules kept from earlier inputs; write roots not in effect: <roots>; the Owner runs atc guard --reset to drop them` |
| `pretooluse legacy` | 不存在，或 entry 仍是舊格式時都不列 | `WARN <path> is the static table of an older entry; atc guard --reset removes it` |

「table 和 policy 不一致」不再是 Owner 要處理的事項。快取過期是正常狀態，下一次 call 會自己重組。

`atc guard` 的結束碼：

- `0`：entries、baseline 都正常，table 也能組合；
- `1`：STOP，token 是上表或 § 5.3 中的一個；
- `retained` 和 `legacy` 只是 WARN，不影響結束碼。

`--json` 欄位：`entries`、`baseline`、`table`（`composes`、`rules`、`inputs`、`cached`、`failure`）、`retained`、`legacy`。

`atc sync --check` 的 `report_hook` 改成只回報 entries、baseline 與「table 組合不出來」，仍然只回報，不讓 sync 失敗。

### 6.1 版本落差先行（version skew）

Owner 11-16 追加這一項。實例：ATC-0049 整合後，主機仍跑 0.6.0，`atc doctor` 報了 5 個 ERROR（各 project 的 integration drift、guard table），卻沒有一行說出根因：已安裝的 `atc` 比 workspace main 舊。

**比較對象。**

- 已安裝的一方：`release_pin.installed()` 的 commit 與 tag，加上 `atc_cli.package_version()`。
- workspace 的一方：`release_pin.history(root)`（content repository，不 fetch）的 `refs/heads/main`，含它的 release tag（`sync_project.merged_release_tags`）和 `atc-manifest.yaml` 的 `min_atc`。
- `adapters/python/pyproject.toml` 的版本只在發版時才改（main 上目前仍是 0.6.0），比不出未發版的落差，所以判斷以 commit 和 tag 為準，版本號只用在 `min_atc`。

**狀態**，依表格順序判斷，第一個成立的就是結果：

| 狀態 | 條件 | 根因行 | 修法 |
| --- | --- | --- | --- |
| development install | `release_pin.editable()` 有值 | `READY`，不比較 | — |
| 沒有安裝紀錄 | `installed()` 是 None | 今天的 `WARN`，不比較 | 今天的 install 指令 |
| `ATC_SKEW_UNKNOWN` | 已安裝的 commit 不在 history repo 裡（例如 cache 還沒 fetch） | `WARN`，不比較 | 跑一次 `atc sync`（會 fetch），或確認安裝來源 |
| `ATC_NOT_ON_MAIN` | 已安裝的 commit 不在 main 的歷史裡 | `ERROR` | 安裝 main 上的 release tag |
| `ATC_BELOW_MIN` | main 的 `min_atc` 高於已安裝的版本 | `ERROR` | 安裝 main 上最新的 release tag（附完整指令） |
| `ATC_BEHIND_RELEASE` | main 上有比已安裝 commit 更新的 release tag | `ERROR` | `release_pin.install_command(url, <最新 tag>)` |
| `ATC_BEHIND_MAIN` | 沒有更新的 tag，但已安裝 commit 之後，main 有 commit 改到 `adapters/python/`、`atc-manifest.yaml`、`shared/` 或 `policies/` | `WARN`，附 commit 數 | 「the Owner tags and installs a release when ready」 |
| 一致 | 以上皆非 | `READY installed atc is main's latest release <tag>` | — |

`ATC_BEHIND_MAIN` 有路徑過濾，因為 main 上經常有只改 task record 或 docs 的 commit，那些不會造成落差。根因行維持 WARN，因為兩次發版之間本來就會落後 main，發版節奏由 Owner 決定。

**輸出。**

- 這一行取代今天的 `installed atc` 檢查，排在 `workspace root` 之後、其他檢查之前，不論有沒有 `-v` 都印。
- 狀態屬於 `ATC_NOT_ON_MAIN`、`ATC_BELOW_MIN`、`ATC_BEHIND_RELEASE`、`ATC_BEHIND_MAIN` 之一時，下列「衍生」檢查原本的 `ERROR` 改成新狀態 `NOTE`，detail 前面加上 `follows from installed atc:`，並緊接在根因行之下印出：
  - `workspace-managed adapters`；
  - `projects.<name>.integration`；
  - `projects.<name>.testkit`；
  - `projects.<name>.pin`，只限 project 比已安裝 release 新的那一種（`release_pin.ahead`）。
- verdict 行多一個計數：`… , N note(s)`。`--json` 的 check 物件多一個 `"follows": "installed atc"`，頂層多一個 `notes` 計數。
- **結束碼**（CLI.md § Exit codes：exit 1 是「a check found problems or drift」）：只要有任何 ERROR 或 NOTE，就 exit 1。只有在沒有 NOTE、而根因行是 WARN（`ATC_BEHIND_MAIN`、`ATC_SKEW_UNKNOWN`、沒有安裝紀錄）時，才 exit 0。換句話說，NOTE 只改變顯示方式和 ERROR 的計數，不會吃掉 drift 本身。
- `pretooluse table` 的組合失敗**不**降級：hook 確實會擋住所有 call，所以它仍是 `ERROR`。有落差時，detail 末尾加上 `the installed atc is older than main; installing the latest release may fix it`。`atc guard` 的同一項也這樣處理。

代價：有落差時，真正獨立存在的 drift 也會暫時以 NOTE 顯示。每個 NOTE 都保留完整的 detail，結束碼仍然是 1，而且裝上 release 之後若仍存在，就會回到 ERROR。

## 7. CLI 變更

- **`atc hook --harness X --workspace FILE --home DIR --atc-home DIR`**：新的正式形式。由 map 組合並使用快取。三個路徑都在 entry 裡，而 entry 位於 protected 的 settings 檔中。hook 不讀 `HOME`、`USERPROFILE`、`ATC_HOME`。
- **`atc hook --harness X [--table FILE]`**：維持今天的 static 模式，讀一份固定的 table，不組合。conformance、測試，以及升級後還沒重跑 `--install` 的舊 entry 都靠它（§ 10）。`--workspace` 與 `--table` 同時給時，以 `USAGE` deny，因為 hook 的錯誤一律 fail closed。
- **`atc guard --install`**：
  - 在 Owner 的 terminal 裡組合，並做 § 5.4 的第 2、3 步；
  - 組合失敗就以 § 5.3 的 token 拒絕，不寫 entry 也不寫 baseline，避免 Owner 裝上一個會擋住所有 call 的 hook；
  - 成功後寫入 baseline（§ 5.2），再寫兩個 harness 的 entry；
  - 不再接受 table 目錄的參數（移除 `engine_command` 的 `--table` 分支）。
- **`atc guard --reset [--yes]`**：Owner 專用，見 § 5.4。
- **`atc add`**：註冊前先組合「加上這個 project 之後」的 table；組合不出來就以 § 5.3 的 token 拒絕，map 不變。
- **引擎的 normalisation**：`uv` 後面、子命令前面的全域選項會被去掉。帶值的選項（`--directory`、`--project`、`--cache-dir`、`--config-file`、`--color`、`--python`/`-p`、`--allow-insecure-host`、`--index-url` 等）連同值一起去掉，作法與 git 的全域選項相同。所以 `uv --quiet tool install x` 會比對成 `[uv, tool, install, x]`。`uv run` 的處理沿用今天的寫法。
- **hard-deny 的增修**（都是在收緊；規則的 schema 不變）：
  - `atc-guard-install`：`with_args` 改成 `[--install, --reset]`，id 和 reason 一併改成涵蓋兩者；
  - `atc-hook-workspace`：`[atc, hook]` 搭配 `with_args: [--workspace]`，`--workspace=x` 也會命中。只有 harness 可以觸發組合；harness 跑 entry 不經過 tool call，所以不受影響；
  - `atc-init-force`：`[atc, init]` 搭配 `with_args: [--force]`，因為重寫 map 是 Owner 的事；
  - `uv-tool-install`／`uv-tool-upgrade`／`uv-tool-uninstall`：`[uv, tool, install|upgrade|uninstall]`。換掉 `atc` 就等於換掉 composer 和引擎；WORKFLOW 已經寫明「agents never install atc」，這條規則把那句話落實成技術限制。

## 10. 從今天寫出的 table 遷移

每台主機在裝好含這項改動的 release 之後，Owner 做一次：

1. **governance checkout 主機**：map 必須有 `governance_checkout: .`。本機目前的 `workspace.yaml` 沒有這一行，所以 `--install` 會先以 `GOVERNANCE_CHECKOUT_UNSET` 拒絕，並給出修法。
2. **`atc guard --install`**：組合、寫入 baseline（舊 `pretooluse.json` 為種子），再寫入新格式的 entry。Codex 會在 `/hooks` 要求再信任一次，因為 entry 的文字變了。

在第 2 步之前，舊的 entry（`atc hook --harness claude`，沒有 `--workspace`）由新的引擎以 static 模式讀舊的 `pretooluse.json`，行為和今天一模一樣：table 會過期，仍然 fail closed。doctor 回報 `ENTRY_OUTDATED`。所以「先裝 release、晚點才跑 `--install`」不會出現保護的空窗。在這段期間，`--reset` 會因為 entry 過期而拒絕（§ 5.4 第 1 步）。

第 2 步之後，舊的 `pretooluse.json` 不再被讀取。doctor 以 WARN 列出它，Owner 想清掉時跑 `atc guard --reset`。

舊的 `atc-maintain guard --hook-out`、`--live-hook-table` 保留給維護者比對用，改從同樣的輸入組合（Git objects 加 map），而不是讀工作樹。
