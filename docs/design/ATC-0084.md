# ATC-0084：related selection 讀專案宣告的 dependents

範圍見 task record `.atc/tasks/ATC-0084.yaml`。§ 1 是現況，§ 2 是宣告與它在 `atc test ID` 的效果，§ 3 是 verifier 與 pre-push gate 的 selection，§ 4 是 workspace root 自己的宣告，§ 5 是 HQT-0077 的實例，§ 6–§ 8 是測試、文件與版本、範圍外的後續，§ 9 是要 Owner 裁決的事。各節寫的是建議選項下的設計；其他選項的差異寫在 § 9。

## 1. 現況

- **related selection 只有兩個來源。** `atc test ID` 的 step 2（`docs/TESTKIT.md` § Commands）以 `[tool.atc-testkit]` `selector` 加 `--direct` 取得 test paths；`testrun.touched`（`atc-testkit/src/atc_testkit/testrun.py:1016-1035`）在 selector 不存在、失敗或最後一行不是 JSON 字串陣列時，退回「tree 裡改動的 test files」。selector 印的是 changed test files 與「直接 import 一個 changed module」的 test files，一條 edge、不取 closure。
- **不 import 就看不到。** 一個 test 以 glob、檔名字串、目錄列舉或子程序讀到的檔，不在 import edge 上，`--direct` 不會選它。
- **hami-quant-trading 沒有宣告 `selector`**（`pyproject.toml` 的 `[tool.atc-testkit]`，main `38239828`）。它的 related run 走 fallback，只跑改動的 test files：HQT-0077 在 `a9cb7401` 的 step report 是 `RELATED 37 changed paths, 6 test paths`、`PASS 200 passed`；6 個就是 diff 裡的 6 個 test files。
- **workspace root 有宣告，但 `--direct` 不讀它。** `adapters/python/scripts/select_tests.py:110-124` 的 `DIRECTORY_READERS` 宣告「讀 graph 看不到的目錄或檔」的 test files，`classify` 用它（`:292-304`），verifier 的 selection 因此選得到；`direct`（`:399-411`）只看 import 與字串 edge，不看 `DIRECTORY_READERS`。`tests/root_reads.py` 在 session 結束時檢查讀 guarded path 卻沒宣告的 test file（`:153`）。
- **shared selection 沒有這個概念。** `atc_testkit.selection.classify`（`selection.py:113-186`）按 path 規則選 test group；`referenced_by` 只看 test 原始碼是否寫出 changed file 的 basename。hami-quant-trading 的 `scripts/prepush_select.py:127` 經由它分類。

## 2. 宣告：`[tool.atc-testkit.dependents]`

### 2.1 位置與形狀

`pyproject.toml`（testkit 目錄那一份，§ Commands 的 test directory）的 `[tool.atc-testkit]` 多一個選填 subtable `dependents`：

```toml
[tool.atc-testkit.dependents]
"scripts/tests/test_mutation_targets.py" = ["scripts/verify_*_mutations.py", "packages/*/src/**/*.py"]
"tests/test_shell_install.py" = ["shared/governance", "shared/skills", "*.md"]
```

- **key** 是一個 test file 或 test directory，相對於 test directory，和 selector 輸出、pytest 收到的 path 同一個基準。
- **value** 是 path pattern 的非空清單，相對於 repository top，和 `RELATED` 計數的 changed paths 同一個基準（`git diff --name-only` 的輸出）。
- 意義：key 讀 value 的檔；value 中任一 pattern 命中一個 changed path，key 就進 related run。
- 以讀者為單位：一個 test file 一行，寫出它讀什麼，review 時對照該 test 的原始碼即可。

### 2.2 pattern

- 以 `/` 分段、大小寫有別，比對 repository top 起算的整條 path。
- `*` 是一段裡零或多個字元，`?` 是一段裡一個字元，`**` 是零或多段。沒有其他特殊字元。
- 不含 `*`、`?` 的 pattern 命中它自己與它底下的一切（目錄前綴）：`shared/skills` 命中 `shared/skills/atc-review/SKILL.md`。
- 不可為空、不可以 `/` 開頭、不可含 `\`、`..` 段或 `.` 段。

### 2.3 與 import edge 合併

related 的 test paths 是三者的聯集，重複的只留一次：

1. selector `--direct` 印的（selector 不存在或失敗時，tree 裡改動的 test files，即現行 fallback）；
2. `dependents` 中，value 有 pattern 命中任一 changed path 的 key；
3. 沒有第三種：宣告不展開 closure，一個被宣告選入的 test file 不再帶入 import 它的 test files。

一個 path 落在另一個已選入的 directory 底下時拿掉，所以 pytest 不會收到同一個檔兩次。宣告只會增加，不會移除 selector 選的。

### 2.4 檢查與 refusal

`atc test ID` 每一種形式（related、`--all`、explicit、`--sha`）都在 step 2 開始時、任何 test 之前檢查 `dependents`。違反時以既有 token `ATC_CONFIG_INVALID`（exit 9）停止，一行寫出 key、entry 與問題，和 `worker_memory_mib` 相同：

| 問題 | 訊息 |
| --- | --- |
| `dependents` 不是 table，或 value 不是非空字串清單 | `dependents: <key>: not a list of path patterns` |
| key 不存在於 tree、在 tree 外，或不是 `test_*.py` 檔、也不是含 `test_*.py` 的目錄 | `dependents: <key>: no such test file or directory` |
| pattern 不合 § 2.2 | `dependents: <key>: <pattern>: invalid pattern` |
| pattern 不命中 tree 的任何 tracked file，也不命中任何 changed path | `dependents: <key>: <pattern>: matches no file` |

- 最後一列擋住過期的宣告：檔案改名後，舊 pattern 會在下一次 run 被指出，不會默默失效。tracked files 對 worktree 是 `git ls-files`，對 export 是 scratch row 的 `source` 中 `git ls-tree -r --name-only <commit>`。changed path 也算，所以刪掉被讀的檔的那次 diff 仍選得到讀者。
- 檢查發生在 scratch 的 registry line 之後，所以 refusal 留下已登記的 scratch，與 step 1 說的「a later one leaves the scratch registered」相同。
- testkit contract check（`atc_testkit.check`，verifier 的 `checks` 列 `TESTKIT_CONTRACT_FAILED`，`verifier.py:451`）跑同一個檢查，所以 candidate、`atc integrate`、pre-push gate 與 CI 也擋得住過期的宣告，不只 writer 的 run。

### 2.5 輸出與紀錄

- 每個因宣告才選入、selector 沒選的 test path，在 `RELATED` 行之前印一行：
  `DECLARED <test path> <- <first changed path it matched>`，命中多個時加 `(+<m> more)`。
- `RELATED <base>: <n> changed paths, <k> test paths` 不變，`<k>` 含宣告選入的。
- stage-time record（§ Stage times）的 `selection_reason`，`related` 時由 `<n> changed paths` 改為 `<n> changed paths, <d> declared`，`<d>` 是 `DECLARED` 行數；`<d>` 為 0 時維持原樣，所以現有紀錄與 `atc test --timings` 不受影響。
- input evidence（§ Input evidence）不變：宣告選入的檔和其他 related 檔一樣被記錄與重用。`dependents` 在 `pyproject.toml` 裡，這個檔已是 input set 的一部分。

## 3. verifier 與 pre-push gate 的 selection

同一份宣告也加進 targeted selection，一個宣告、每種 selection 都讀：

- `atc_testkit.config.dependents(root)` 讀並檢查 table（§ 2.4），回傳 `{test path: patterns}`。`atc test ID`、contract check 與下面兩處都用它。
- shared `selection.classify`：`SelectionPolicy` 多一個欄位 `dependents`（預設空）。每個 path 依現有規則分類後，若沒有 widen，再把「包含每個命中 key 的 test group」加入，理由 `declared dependent <key>`。key 不落在任何 `test_order` group 內時，`SelectionPolicy.__post_init__` 以 `ValueError` 拒絕，和既有的 `unknown test consumers` 相同。
- verifier 與 gate 的 selection 若已是 full suite，宣告不改變什麼；宣告只會讓 targeted selection 變大，不會讓它變小。
- candidate 的 `selection_reason` 在 `full` 時不變；targeted 時，它的 reason 清單多出 `declared dependent` 那幾行。

## 5. HQT-0077 實例

hami-quant-trading，branch `claude+HQT-0077`，FAIL 的 tip `a9cb7401`，base `38239828`。candidate 失敗 6 個（reviewer verdict `HQT-0077-a9cb7401…-review.md`）：

- **`scripts/tests/test_mutation_targets.py`（3 個 case）。** 它以 `(ROOT / "scripts").glob("verify_*_mutations.py")`（`:22`）列出 67 個 script，import 每一個，再檢查每個 mutation 的 target 文字在被 mutate 的檔中正好出現一次（`:200-203`）。被讀的有兩類：script 本身，以及 script 指向的 product 原始碼（`packages/*/src/…`，`scripts/` 的檔）。HQT-0077 改了 `account_writer.py`、`ledger.py`、`activation_expectation.py`，三個 script 的 target 因此失效。兩類都不在 import edge 上，需要宣告：

  ```toml
  [tool.atc-testkit.dependents]
  "scripts/tests/test_mutation_targets.py" = ["scripts/verify_*_mutations.py", "packages/*/src/**/*.py", "scripts/*.py"]
  ```

  在 `a9cb7401` 的 37 個 changed paths 上，`packages/*/src/**/*.py` 命中 `account_writer.py` 等，輸出 `DECLARED scripts/tests/test_mutation_targets.py <- packages/trading-cli/src/hami_quant_trading_cli/account_writer.py (+N more)`，這 3 個失敗會在 writer 的 run 出現。代價：任何 product 原始碼的改動都帶上這個檔。它不跑 mutant，但含 `collected()` 的 `--collect-only` 子程序（`COLLECT_TIMEOUT = 600`），實際秒數要由 Hami-Coordinator 在宣告時從 `atc test --timings` 量。

- **ledger 目錄的 3 個 test。** `packages/trading-cli/tests/test_check_signals.py:240`、`:590` 與 `test_runtime_ingest.py:41` 斷言 ledger 目錄裡的檔案集合，新的 `signal-ledger.jsonl.append-lock.lock` 讓它們失敗。這兩個檔直接 import `hami_quant_trading_signals.ledger`（`test_check_signals.py:18`、`test_runtime_ingest.py:10-11`），而 HQT-0077 改了 `ledger.py` 與 `symbol_lock.py`：它們本來就在 import edge 上。漏掉的原因是 hami-quant-trading 沒有 `selector`（§ 1），不是缺宣告。把它們寫進 `dependents` 是拿宣告補 import graph，宣告會隨每次 import 變動而過期；正確的補法是該專案有一個 `--direct` selector（§ 9 D6）。

## 6. Conformance 與測試

行為由 `adapters/python/tests/` 的這些檔釘住：

- `test_testkit_dependents.py`（新增）：`config.dependents` 對 § 2.4 每一列各一個 refusal case；pattern 語法：`*` 不跨段、`**` 零段與多段、無萬用字元時的目錄前綴、大小寫有別；刪除的檔只在 changed paths 中時仍算命中。
- `test_testkit_testrun_flags.py`：沿用 `:150-201` 的小 repo fixture——
  - 宣告命中時 `DECLARED` 行與 `RELATED` 的 `<k>`；
  - 沒有 selector 時宣告仍加在 fallback 上；
  - selector 已選的檔不印 `DECLARED`；
  - 已選目錄底下的檔被拿掉；
  - 過期 pattern 在 `--all` 與 explicit run 也以 `ATC_CONFIG_INVALID` exit 9 停止，且沒有 test 跑。
- `test_timings.py`：`selection_reason` 在 `<d>` 為 0 與大於 0 時的兩個值。

- `test_testkit_check.py`：過期 pattern 讓 `atc_testkit.check` 回報 problem。
- `test_select_tests.py` 與 `root_reads.py`：`DIRECTORY_READERS` 的三個 monkeypatch（`:49`、`:80`、`:237`）改為改寫讀入的 dependents；加一個 case 證明 `direct` 經由 `atc test` 選得到宣告的讀者。

## 9. 要 Owner 裁決的事（Decisions for the Owner）

每項一個決定，建議的選項在前。

### D1 宣告的位置

- **A（建議）`[tool.atc-testkit.dependents]`，由 testkit 讀**（§ 2.1）。改變：每個專案寫法相同；沒有 selector 的專案（hami-quant-trading）也生效；檢查與 refusal 只有一份實作。
- **B 由各專案 selector 的 `--direct` 輸出負責。** testkit 不變，每個 selector 自己讀自己的宣告。改變：hami-quant-trading 要先寫 selector 才能宣告；root 的 `direct` 要自己補 `DIRECTORY_READERS`；過期檢查各寫一份。
- **C 放在專案 Python 檔的 `SelectionPolicy`。** 改變：只有用 shared selection 的專案能用；`atc test` 要 import 專案的 policy module 才讀得到，`touched` 目前不 import 專案碼。

### D2 宣告的形狀

- **A（建議）test path → pattern 清單**（讀者為單位，§ 2.1）。改變：一個 test 讀什麼集中在一行，與 root 現有的 `DIRECTORY_READERS` 同形。
- **B pattern → test path 清單**（被讀的檔為單位）。改變：一個 pattern 被多個 test 讀時只寫一次；同一個 test 的讀取分散在多行，test 改寫時較難找齊要刪的行。

### D3 verifier 與 pre-push gate 是否也讀

- **A（建議）也讀**（§ 3）。改變：shared `classify` 與 root `select_tests` 加入宣告；targeted candidate 不會再漏同一批 test；`SelectionPolicy` 多一個欄位。
- **B 只有 `atc test ID` 讀。** 改變：testkit 改動較小；verifier 的 targeted selection 仍靠 `referenced_by` 與專案規則，宣告過的 test 可能在 writer 的 run 被選、在 candidate 卻沒被選，兩邊選得不一樣。

### D4 過期的 pattern

- **A（建議）refusal，`atc test` 每種形式與 contract check 都擋**（§ 2.4）。改變：改名後下一次 run 就停，要在同一個 commit 改宣告。
- **B 只印警告。** 改變：run 照跑；宣告可能默默失效，正是本 task 要修的那類漏選。
- **C 不檢查。** 改變：最簡單；失效的宣告只能靠 review 發現。

### D5 root 的 `DIRECTORY_READERS`

- **A（建議）搬進 `[tool.atc-testkit.dependents]`，`select_tests.py` 與 `root_reads.py` 改讀它**（§ 4）。改變：一個問題一個機制；root 的 `--direct` 從此選得到這些讀者；比對改成大小寫有別。
- **B 保留兩者。** 改變：root 的 `DIRECTORY_READERS` 照舊，另在 `dependents` 再寫一次給 `--direct`；兩份要人工保持一致，reviewer step 5 會把它當成「同一問題的第二個機制」。

### D6 沒有 `--direct` selector 的專案（§ 5 的 ledger 案例）

- **A（建議）另開一個 ATC task，讓 testkit 在專案沒有 `selector` 時提供預設的 import-edge `--direct`。** 預設實作從 step 4 已知的 `packages/*/src` 與 `src` 把 changed path 對應到 module，再以 `ast` 掃 test files 的 import。改變：每個專案都有一條 edge，宣告只補 import 以外的讀取；它是另一個機制，有自己的 conformance，分開審查較好。
- **B 併入本 task。** 改變：同一個 release 修好 HQT-0077 的兩類漏選；本 task 的 review 範圍變大。
- **C 不做，由 hami-quant-trading 自己寫 selector**（Hami-Coordinator 的 follow-up）。改變：ATC 不變；每個沒有 selector 的專案各自補，在那之前只靠 changed test files。
