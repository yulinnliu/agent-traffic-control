## 1. 讀者的界線

- **使用者**：在 workspace 與其專案跑 `atc` 的人。包括 Owner、writer／reviewer／coordinator session，以及 vendor 了 testkit、為自己專案寫測試、CI、verifier argv 檔與 hard-deny policy 的專案維護人。
- **ATC maintainer**：修改 `atc`、`atc-testkit` 本身的人，或操作只屬於本 repository 的工具（root 的 verifier、`check.ps1`、docs site、release）的人。

判斷規則：一段內容若只描述本 repository 自己的工具，或 `atc`／`atc-testkit` 的內部構造（模組、環境變數的內部傳遞、檔案格式的內部欄位），而使用者既不執行它、也不會在輸出中看到它，就是 maintainer-only；使用者會執行、會看到其輸出或拒絕 token、或要照著寫自己專案設定的，是使用者的。兩者混在一節的是 mixed。

這條界線把「專案的 testkit 整合者」算作使用者（§ 12 D1）。證據：已註冊專案自己寫的文件與程式碼引用 TESTKIT 的 § Private desktop（hami-quant-trading `scripts/mutation_pytest.py:1`、`scripts/tests/README.md:41,48`、`scripts/tests/test_mutation_pytest.py:2`）、§ Stages（`scripts/tests/README.md:34`、`.github/workflows/ci.yml:64`）、§ Time slack（`scripts/tests/trading_app_timing.py:10`；my-heartopia-tools `scripts/integration-verify.mjs:24`）、§ Documentation check（`scripts/check_doc_refs.py:3`）、§ Input evidence（hami-quant-trading `AGENTS.md:339`）與整份 `ENFORCEMENT.md`（§ 5）。
