# ATC-0063 設計：`atc integrate` 顯示步驟、測試效率可依 project 與版本量測

範圍見 task record `.atc/tasks/ATC-0063.yaml`。§ 1 是三件事的實測根因，§ 2–4 是各自的設計，§ 5 是文件，§ 6 列出要 Owner 裁決的事項，§ 7 是與 ATC-0062 的檔案交集。

## 1. 實測

### 1.1 integrate 為何看起來卡住

`build_and_verify`（`git_integrate.py`）在 verifier 開始前印一行 `verify: candidate <sha> … timeout 1800s`，之後 `_run_verifier` 把 verifier 的 stdout/stderr 寫進 `<tmp>/systmp` 的暫存檔（不用 pipe，避免活得比 verifier 久的子孫行程卡住 wait），每 `WAIT_POLL`（5 s）醒一次只檢查 timeout 與 host worker 排隊時間。verifier 的 `ELAPSED`、`WAIT host workers`、`<stage>: REUSED <n> files, RUN <m> files` 都已即時 flush 到那個暫存檔，只是沒人讀。log `<candidate>.verify.log` 在結束時才由兩個暫存檔組成，所以路徑也只能在結束時印。fetch、preflight、candidate build、fast-forward、ledger 都沒有進度行。

### 1.2 `atc push` 的重複輸出

讀過的路徑都只寫一次：

- `git_streamed`（`git_preflight.py`）以 `read1` 取得的每個 chunk 只寫一次到 stderr，incremental decoder 不會重送位元組。
- `gate.main` 只印一次 `selection.describe(chosen)`；hqt 的 `prepush_select.select` 每個路徑只加一條 reason；hqt 只有一個 `origin` URL，所以 pre-push hook 只跑一次。
- 唯一設計上的重複：push 失敗時 `PUSH_FAILED` 的 refusal 會在 stdout 重印輸出的最後 20 行。
- `--progress` 只在 stderr 是 terminal 時加入。git 的進度行用 `\r` 覆寫同一行。

所以由程式碼看不出重複的來源。候選原因：(a) 那次 push 失敗，看到的是 `PUSH_FAILED` 的尾段；(b) console 重繪：ConPTY（Windows Terminal、desktop app 的 Terminal panel 都用它）在視窗大小改變或 `\r` 進度行與長行換行混在一起時，會重送可見區域，而 xterm 類前端把重送的內容加進 scrollback。實作時用沙盒重現來分辨（§ 3）。

### 1.3 `timings.jsonl` 基線（11-17）

532 筆：`mutants` 351、`test` 119、`verify` 62。`verify` 中 42 筆 `task: ""`，時間在 11-15T15:39Z 到 11-16T08:56Z；第一筆有 task 的 `verify` 在 11-16T11:28Z。根因是版本落差：`ATC_TASK` 與 stage record 同在 `cb02e16` 加入，verifier 跑的是 candidate tree 裡的 testkit（已會讀 `ATC_TASK`），但 v0.7.0（11-16T08:47Z tag）裝上之前，主機上的 `atc` 是不會設 `ATC_TASK` 的舊版。v0.7.0 之後沒有空 task 的 verify。現在仍會留空的只剩：一次 integration 綁多個 task 時（`task=None`），以及不經 `atc` 手動跑的 verifier。pre-push gate 不寫任何 record。

## 2. `atc integrate` 的步驟行（atc）

### 2.1 共用 `Steps`

`push.py` 的 `Steps` 搬到 `cli_conventions.py`（`atc push` 與 `atc integrate` 共用一份，避免兩套機制），格式不變：`STEP <step> <name> <seconds>s <result>`，寫 stderr；需要即時輸出的步驟另有開始行 `STEP <step> <name> 0.0s START <what>`。`<name>` 是 project 名（`root` 或 `workspace.yaml` 的名稱）。

### 2.2 步驟與結果

| step | 範圍 | result |
| --- | --- | --- |
| `fetch` | `resolve` 的 `git fetch origin` | `OK`、`FAILED`、`none`（沒有 origin） |
| `preflight` | `merge_preflight` 與 reuse check | `FF`、`NO_FF`、`STOP <reason>` |
| `candidate` | detached worktree、`NO_FF` 的 merge | `OK <sha12>`、`REUSED`（`FF` 且重用時不建）、token |
| `verify` | verifier、record check 或重用 | `PASS`、`REUSED <record>`、`RECORDS_ONLY PASS`、token |
| `fast-forward` | candidate ref、`merge --ff-only` | `OK <main_before12>..<main_after12>`、token |
| `ledger` | `_note_integration` 與 evidence | `OK`、`WRITE_FAILED` |

實際順序是 fast-forward 在 ledger 前（ledger 記的是已進 `main` 的 candidate），表依實際順序列。步驟中途 refusal 時，該步印出它的 token 為 result，之後的步驟不印。

`verify` 另有開始行：`STEP verify <name> 0.0s START <candidate12> timeout <s>s (<source>) log <path>`，取代今天的 `verify: candidate …` 行；evidence 原因（`RUN (evidence: …)`）照舊放在同一行。

### 2.3 verifier log 即時寫入、即時轉印

- log 在 verifier 啟動前建立：先寫 header（time、platform、working directory、command），接 `--- stdout ---`，然後直接作為 verifier 的 stdout 檔（取代暫存檔，仍是檔案不是 pipe，子孫行程問題不變）。stderr 仍寫暫存檔。結束時在 log 尾端補 `--- stderr ---`、stderr 內容、`exit: <code|timeout>`，排隊時間行照舊。`exit` 由 header 移到尾端：這是業界 CI log 的做法（狀態在結束時才存在），`docs/TESTKIT.md` § Running and logging 的 header 本來就不含 exit。
- `_run_verifier` 的等待迴圈每次醒來（`WAIT_POLL` 改為 1 s，只影響轉印延遲）讀 log 的新位元組，以完整行為單位轉印到 stderr，每行加 `  verify: ` 前綴。轉印 verifier stdout 的全部行，不只 `ELAPSED`：那裡只有 verifier 自己的行（`ELAPSED`、`WAIT host workers`、`REUSED/RUN`、workers 行、`selection:`、`classification:`），pytest 輸出在各 stage 自己的 log。結束時補讀最後一段。
- `--json` 照舊只在 stdout 印一個 JSON 物件；步驟行與轉印都在 stderr。`--check` 不跑 candidate，不印步驟行，stdout 與 stderr 都不變。

### 2.4 `atc test ID --candidate`

走同一個 `build_and_verify`，所以有 `candidate`、`verify` 步驟行與轉印。它今天在 `PASS candidate` 行前把 log 裡的 `ELAPSED` 行重印到 stdout（`_elapsed_lines`）；轉印之後同一行會在終端出現兩次，所以拿掉重印（§ 6 裁決 1）。`PASS candidate … log <path>` 這最後一行不變，reviewer 照舊引用它。

## 4. 測試效率可量測（testkit 寫，atc 設 input 並出報表）

### 4.1 record 新欄位

`elapsed.Clock` 寫的每筆 record 加以下欄位。舊欄位與意義不變；讀者遇到缺欄位的舊 record 當作「未記錄」。`elapsed.records` 本來就把每行當 dict 讀，沒有別的讀者。

| 欄位 | 型別 | 值 |
| --- | --- | --- |
| `project` | string | `ATC_PROJECT`；沒有時取 Git common dir 的上層目錄名（candidate 與 worktree 都指回主 checkout）；都沒有時 `""` |
| `atc_version` | string | `ATC_VERSION`（`atc` 啟動 testkit 時設）；沒有時 `""` |
| `testkit_version` | string | 執行中的 `atc_testkit.__version__`（project 的 vendored 版本） |
| `passed`、`failed`、`skipped` | int 或 null | 該 stage log 最後一行 pytest summary 的計數（`errors` 併入 `failed`）；`checks` stage、非 Python toolchain 與讀不到 summary 時為 null |
| `selection` | string | `full`、`related`、`explicit`、`none`、`documentation-only` |
| `selection_reason` | string | 見 § 4.2 |
| `reused_files`、`run_files` | int 或 null | verifier stage 的 `REUSED <n> files, RUN <m> files`；沒有 evidence 判斷的 stage 為 null |

`ATC_PROJECT`、`ATC_VERSION` 與 `ATC_TASK` 一樣是選用 input：`atc test`、`atc test --mutants`、`atc test --candidate`、`atc integrate` 與 `atc push`（經 git 的 hook 環境繼承）設它們，其他呼叫者不設也照跑。

### 4.2 selection 與 reason

| 命令 | `selection` | `selection_reason` |
| --- | --- | --- |
| `atc test ID` | `related` | `<n> changed paths` |
| `atc test ID --all` | `full` | `--all` |
| `atc test ID -- ARGS` | `explicit` | `pytest arguments` |
| `atc test ID --mutants` | `explicit`（baseline 與 mutant 的測試清單） | `<n> tests` |
| verifier、gate | 依 `Selection.pytest_paths()`：`[]` 為 `full`，清單為 `related`，`None` 為 `none`；documentation-only 範圍為 `documentation-only` | `full` 時是第一條 `-> full suite` 的 reason 加 `(+<k> more)`；否則 `<n> changed paths` |

### 4.3 每筆 verify record 都帶 task

- `ATC_TASK` 在一次 integration 綁多個 task 時給全部 task ID，以 `,` 連接（task ID 不含逗號）。單一 task 不變。
- gate：`atc push` 由 ledger 已知要推送的 commits 屬於哪些 integration，把它們的 task 以 `,` 連接設為 `ATC_TASK`，git 把環境傳給 hook。手動 `git push` 時為 `""`。
- 不經 `atc` 的 verifier 仍是 `""`，這是 § Stage times「沒有 input 給值」的定義，不再是缺陷。

### 4.4 pre-push gate 寫 record

`gate._run_tests` 把 `Clock` 傳給 `run_stages`：`command` 為 `prepush`，`sha` 為推送的 commit（多個時取最後一個 ref 的），`task` 見 § 4.3。static checks 合成一個 `checks` stage，與 verifier 相同（`_Checks.report_checks` 的作法移到共用處）。每個推送的 commit 都被 evidence 覆蓋時不跑 stage，寫一筆 `stage` 為 `reused`、`seconds` 0、`result` `REUSED` 的 record；`atc integrate` 重用 `--candidate` 紀錄而不跑 verifier 時，也寫一筆同樣的 `verify` record。如此重用率的分母包含整次重用。

### 4.5 報表：`atc test --timings`

`atc test --timings [--project NAME] [--since DATE] [--json]`，與 `--list` 同屬不需 task 的子功能。實作在 atc（`task_tests.py`），讀 `elapsed.records`；舊 record 沒有 `project` 時，由 task ID 前綴對 `workspace.yaml` 的 project 推得（`ATC` → `root`），推不出的歸 `-`。

人讀輸出，每 (project, atc, testkit) 一行，舊 record 的版本顯示 `-`：

```text
project             atc    testkit  runs  tests   test-s   s/test  full  full-s  reuse
root                0.8.0  0.15.0     41   3120   1543.2    0.49     3   612.0   38%
hami-quant-trading  -      -          12      -    922.5       -     1   701.3     -
```

- `runs`：該組不同 (command, sha, time 分鐘) 的次數；`tests` 為 `passed+failed+skipped` 合計；`test-s` 為 pytest stage 秒數合計（不含 `checks`）；`s/test` = `test-s / tests`，只用有計數的 record。
- `full`、`full-s`：`selection` 為 `full` 的次數與每次平均秒數。
- `reuse`：`reused_files / (reused_files + run_files)`，整次重用（§ 4.4）以該次 stage 的檔案數計入分子；沒有資料為 `-`。
- 第二段每個 `command` 一行同樣欄位，用來分開 `test`、`mutants`、`verify`、`prepush`。
- `--json`：`{"command": "atc test --timings", "verdict": "OK", "exit_code": 0, "hint": null, "groups": [...]}`，每組是上表欄位加 `command` 細分。

`CLI.md` § Output 寫「`atc test` takes no `--json`」，要改成例外：`--list` 與 `--timings` 收 `--json`（`--list` 今天其實已收）。新增選項是相容變更，不需版號。
