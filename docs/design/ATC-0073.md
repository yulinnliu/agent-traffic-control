### 1.4 複製讓相同 SHA 變多

- 複製來的 repo 內容與時間相同，不同 test 在同一秒做的同樣 commit 會得到同一個 SHA。
- `test_testkit_gate.py` 的 `gate_records` 以 SHA 從 session 共用的 worker pool 讀 stage-time records，改前的量測已因此失敗一次（`test_a_failing_check_is_recorded_and_runs_no_stage` 讀到別的 test 的 5 筆 record）。
- 現在每個 test 的 `repo` fixture 以 `ATC_WORKER_POOL_DIR` 指向自己的 pool，只讀到自己的 records。其餘移過的檔沒有跨 test、以 SHA 為鍵的共用狀態。

## 2. `test_a_live_process_running_from_the_environment_is_found`

- 判定：test 錯，`atc doctor` 對。不是 behaviour 修正。
- test 用 `sys.executable` 啟動子行程，在 venv 裡那是 launcher，launcher 再啟動 base interpreter 為第二個行程，兩者的 command line 都含 script 路徑。test 只 kill 並 wait launcher；interpreter 由 launcher 的 job 結束，時間不在 test 的 wait 之內。test 的第一個 assertion（`1 processes`）表示它在 interpreter 還沒列出時就 kill 了 launcher。
- 量測：一個被 kill、被 wait 的行程，即使 handle 還開著，20 ms 內就不在行程清單裡（35 次）；所以 doctor 不會把已結束的行程算進去，10 s 後仍 `WARN` 表示當時還有一個從 prefix 執行的行程活著。doctor 回報它正確。
- 在無負載與 CPU 滿載下各 30 次「launcher 一列出就 kill」都沒重現 interpreter 留下；能留下的窗口是 launcher 已啟動 interpreter、尚未把它放進自己的 job。
- 修正：子行程改用 `sys._base_executable`，只有一個行程，kill 並 wait 的就是它。
