atc 0.10.0 (atc-testkit 0.17.0)

atc 0.10.0 runs the lint stage over every file of the tree at each entry
but the commit hook, so a rule that changed, in a topic or through
`atc sync`, checks the files it did not touch at the next `atc test` and
at the integration verifier, not first in CI. `atc integrate` and
`atc test ID --candidate` ask git each read-only question once per
invocation, which makes them faster with the same output. atc-testkit
0.17.0 carries the whole-tree lint stage into a project's verifier, and a
verifier under a non-Python toolchain reads no input set. Removed names
keep no alias.

## Breaking

The lint stage (ATC-0070, testkit 0.17.0):

- **Scope.** `atc test ID`, `atc test ID --lint` and the integration
  verifier run the repository's `.pre-commit-config.yaml` over every file of
  the tree. Before, `atc test` linted the files changed since the record's
  `base_sha` plus the untracked ones, and the verifier linted the range
  (`--from-ref <ATC_EXPECTED_MAIN_SHA> --to-ref <ATC_INTEGRATION_SHA>`). The
  verifier's lint row is now `pre-commit run --all-files` in the candidate.
  The commit hook (staged files) and CI are unchanged.
- **Untracked files.** In a task's worktree the run lints through a copy of
  the worktree's index, `<scratch>/lint.index`, to which it adds every file,
  untracked ones included; pre-commit and every hook run with
  `GIT_INDEX_FILE` naming the copy, which is deleted when pre-commit ends.
  The worktree's own index is never written. A hook that removes the
  `GIT_*` variables, such as `atc_testkit.docs --tracked`, reads the
  worktree's own index and skips untracked files until they are added.
- **Output.** A pass prints `LINT PASS every file; log <path>` (was
  `LINT PASS <n> files; log <path>`); a failure prints
  `STOP LINT_FAILED: pre-commit exited <code>; log <path>` (was
  `... exited <code> on <n> files; ...`). `LINT no changed file` is
  removed. The tokens `LINT_FAILED` and `LINT_NOT_CONFIGURED` are unchanged.
- **Records without `base_sha`.** `atc test ID` and `atc test ID --lint`
  run the lint stage for them too. Before, `atc test ID` ran no lint stage
  for such a record, and `atc test ID --lint` stopped with the usage error
  `--lint-only takes --lint and no tests` (exit 2).
- **After `atc sync`.** When sync delivers stricter rules to a project's
  `.atc/lint/`, every topic of that project whose tree still holds a file
  they reject fails the lint stage, at `atc test` and at the verifier, until
  a commit on `main` fixes the file. The lint stage has no bypass, and sync
  prints no note.
- **Cost.** The workspace root's lint stage takes about 20 seconds more per
  run (about 28 seconds in all on the Windows host), a project's a few
  seconds (`docs/design/ATC-0070.md` § 2).
- **testkit API.** `python -m atc_testkit.testrun --lint` is a flag and
  takes no SHA (was `--lint SHA`). In `atc_testkit.lint`, `range_argv`,
  `files_argv`, `existing` and `run_paths` are removed; their replacements
  are `tree_argv(python)` and `run_tree(top, place, python, env, log)`.
  `atc_testkit.testrun.run_lint` takes no paths.

The verification report (ATC-0073, testkit 0.17.0):

- **Non-Python toolchain.** The verifier reads no input set under a
  non-Python toolchain, so its verification report's `inputs` is `null`.
  Before, it classified the input set and wrote it, although its stages used
  no input evidence. It still prints
  `input evidence: not used by the <toolchain> toolchain` before the stages.
  `null` is a value `atc-verification-report/3` already allows
  (`shared/conformance/verification-evidence/README.md`); `atc integrate`
  matches no other tree to such a report by its input digest.

`atc integrate` and `atc test ID --candidate` (ATC-0072): no output,
token or exit code changes. One invocation keeps the answer of each
read-only git query until something may have changed it; the re-reads that
detect another process moving `main` or the source branch, and the
integration checkout's status check, always ask git.

ATC-0071 and the test half of ATC-0073 change only the root repository's
tests (`adapters/python/tests/git_history.py` and its users) and nothing a
user runs.

## atc-testkit 0.17.0

A project vendors one testkit wheel (`vendor/atc-testkit.json`) and keeps it
until it upgrades. `atc test` runs from the atc-testkit that installs with
`atc`; the project's verifier and pre-push gate run from its vendored one.
The projects vendor 0.15.0, so an upgrade to 0.17.0 also takes the 0.16.0
rows of `docs/releases/v0.9.0.md`.

| Change | Runs from | Project upgrade |
| --- | --- | --- |
| The lint stage over every file of the tree (ATC-0070) | the installed `atc` (`atc test ID`, `atc test ID --lint`); the project's vendored testkit (verifier) | skippable, at a cost. Once the host installs 0.10.0, `atc test` lints the whole tree of every project that holds `.pre-commit-config.yaml`, whatever testkit it vendors, so hami-quant's and hami-quant-trading's topics meet any existing violation at `atc test`. Their verifier on 0.15.0 or 0.16.0 still lints only the range, so a rule changed by a topic or by `atc sync` reaches the files it did not touch first in CI. A project adopting the lint stage (`docs/TESTKIT.md` § Upgrading a project's testkit, step 7) gets a verifier that checks every file only on 0.17.0 |
| A non-Python toolchain's verifier reads no input set; the report's `inputs` is `null` (ATC-0073) | the project's vendored testkit (verifier) | skippable: an older verifier under a non-Python toolchain classifies and records an input set its stages never use, which costs that classification's time. The testkit knows only the `python` toolchain (`atc_testkit.toolchain.MODULES`), so no project's verifier takes this path today |

`min_atc` in `atc-manifest.yaml` stays 0.8.0. atc-testkit 0.17.0 writes
the same `atc-verification-report/3`, evidence and stage-time formats as
0.16.0, and `inputs: null` is a value `/3` defined from the start, which
atc 0.8.0 reads.

## First run

No new tool or hook environment. A task whose record has no `base_sha` now
runs the lint stage at `atc test`, so its first run on a host builds the
hook environments if no earlier run did (`docs/TESTKIT.md` § Lint stage).

## Tasks

- ATC-0070: the lint stage checks every file of the tree at `atc test` and
  at the integration verifier, untracked files included in a worktree, so a
  changed rule meets the files it did not touch at the next run.
- ATC-0071: the root test suite's time measured and its fixture
  repositories built once per session; no behaviour change.
- ATC-0072: `atc integrate` and `atc test ID --candidate` ask git each
  read-only question once per invocation; same output, faster.
- ATC-0073: a verifier under a non-Python toolchain reads no input set and
  reports `inputs` `null`; the rest is root test debt, no behaviour change.
- ATC-0074: this release.

## Upgrade

The Owner's steps on each host, in this order:

1. Run no `atc test`, verifier or other `atc` command while uv replaces `atc`: `atc doctor`
   reports its `atc environment` line READY. On Windows, rerun the install after a `WinError 32`.
2. On a host that did not create `v0.10.0`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host installs
   from GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.10.0#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.10.0#subdirectory=adapters/python"
   ```

4. From the Owner's own terminal, one command per line:

   ```text
   atc sync --check
   atc sync
   atc doctor
   ```

   The hook table is unchanged since 0.7.0, so `atc guard --install` is not
   rerun. `atc doctor` reports `atc 0.10.0` at `v0.10.0` with its commit,
   and exits 0 once every check is READY, WARN or NOT_INITIALIZED.
5. Replace changed names in scripts and briefs:
   - a script that matched `LINT PASS <n> files`, the file count in
     `STOP LINT_FAILED`, or `LINT no changed file` matches the lines in
     § Breaking, The lint stage;
   - a direct call of `python -m atc_testkit.testrun --lint SHA` drops the
     SHA.

### Projects

Re-sync on 0.10.0 (`atc sync <project>`, or `atc sync` for all). Until a
project's `.atc/atc.lock` pins v0.10.0, the task flow stops there with
`STOP RELEASE_MISMATCH`. No skill, governance rule or lint rule changed, so
the re-sync moves the pin only. A project keeps its vendored testkit through
the re-sync.

From the install on, `atc test ID` in a project that holds
`.pre-commit-config.yaml` (hami-quant, hami-quant-trading) lints every file
of its tree. A file on that project's `main` that its rules reject fails
every topic's `atc test` until a commit on `main` fixes it. Before the
install, run the project's rules over its whole tree in a worktree of the
project on `main` to find such a file first:

```text
uv run python -m pre_commit run --all-files
```

Upgrading a project's vendored atc-testkit to 0.17.0 goes through
Hami-Coordinator. This version's delta for a project that upgrades:

- the verifier lints every file of the candidate, so the project's tree
  passes its own rules whole before the first integration on 0.17.0;
- a caller of `atc_testkit.lint.range_argv`, `files_argv`, `existing` or
  `run_paths` moves to `tree_argv` or `run_tree`.

A project that upgrades its
vendored atc-testkit follows [Upgrading a project's testkit](../TESTKIT.md#upgrading-a-projects-testkit).
