atc 0.9.0 (atc-testkit 0.16.0)

atc 0.9.0 shows where `atc integrate` is while it runs and runs a
repository's pre-push hook before `atc push` connects to origin. `atc test ID
-- ARGS` runs exactly the pytest arguments given. Each stage-time record in
`timings.jsonl` names its project, versions, test counts, selection and
reuse, the pre-push gate writes records too, and `atc test --timings`
reports test efficiency per project and version. `atc doctor` lists the
processes that would make `uv tool install --force` fail. atc-testkit 0.16.0
tells the files ATC manages in a project from what `atc sync` writes there,
so a sync commit no longer widens a project's gate to its full suite, and a
project upgrades its vendored testkit by one procedure,
[Upgrading a project's testkit](../TESTKIT.md#upgrading-a-projects-testkit).
The documentation is published at
<https://yulinnliu.github.io/agent-traffic-control/>, and the maintainer
documents live under `docs/development/`. Removed and renamed names keep no
alias.

## Breaking

`atc test` (ATC-0067, ATC-0063):

- **`atc test ID -- ARGS`** runs exactly `ARGS`, with no related selection,
  with or without `--all`. Before, it added the related tests in front of
  `ARGS`, and a task with no related test printed `NO_TESTS no test
  selected` and exited 0 without running the named files. Such a run's log
  label and stage are `explicit`, and its stage-time record has `selection`
  `explicit`, `selection_reason` `pytest arguments`. It records no input
  evidence. `atc test ID` with nothing after `--` is unchanged. The lint
  stage still runs first over the files changed since `base_sha`.
- **`atc test ID --candidate`** no longer repeats the verifier's `ELAPSED`
  lines on stdout before its `PASS candidate` line. They appear once, on
  stderr, as the verifier prints them.
- **`atc test --timings [--project NAME] [--since DATE] [--json]`** is new.
  It reports `~/.atc/run/timings.jsonl` per project, atc version and testkit
  version (`docs/TESTKIT.md` § Stage times). `atc test` takes `--json` with
  `--list`, `--candidate` and `--timings`.

Stage-time records (ATC-0063, testkit 0.16.0 for the verifier and the gate):

- **New fields.** Each record adds `project`, `atc_version`,
  `testkit_version`, `passed`, `failed`, `skipped`, `selection` (`full`,
  `related`, `explicit`, `none` or `documentation-only`),
  `selection_reason`, `reused_files` and `run_files`.
- **New values.** `command` adds `prepush`, written by the pre-push gate,
  which wrote no record before. A verifier or gate run that a covering record
  replaced whole writes the stage `reused` with the result `REUSED`, and a
  verifier stage whose every file a record covered has the result `REUSED`.
- **Inputs.** `ATC_TASK` names the run's tasks joined by `,`. The verifier
  and the gate read the new optional inputs `ATC_PROJECT` and `ATC_VERSION`.
  `atc test`, `atc integrate`, `atc test ID --candidate` and `atc push` (in
  the hook's environment) set all three.

`atc integrate` (ATC-0063):

- **Progress lines.** stderr shows one
  `STEP <step> <project> <seconds>s <result>` line as each of `fetch`,
  `preflight`, `candidate`, `verify`, `fast-forward` and `ledger` ends, also
  under `--json`. A refusal's token is the result where a step stops.
  `verify` also prints a `START` line naming the verifier's log, and the
  verifier's stdout follows as `  verify: ` lines while it runs.
  `atc integrate --check` prints no step line. Stdout keeps the verdict lines
  and the `--json` object.
- **Live verifier log.** `<candidate>.verify.log` is written from the start:
  the header, then the verifier's stdout as it prints it. When the verifier
  ends, the log is rewritten as the header, `--- stdout ---`, the stdout,
  `--- stderr ---`, the stderr and `exit: <code>` last.

`atc push` (ATC-0063):

- **Gate step.** `atc push` runs the repository's pre-push hook with
  `git hook run` before git connects to origin, giving it what `git push`
  would: the remote's name and push URL as arguments and
  `refs/heads/main <sha> refs/heads/main <origin/main>` on stdin. It prints
  `STEP gate <name> 0.0s START <sha12>` and `STEP gate <name> <seconds>s OK`
  or `FAILED exit <code>`, with the hook's output streamed between them. A
  failing hook is `GATE_FAILED`, exit 2, and nothing connects.
- **Push.** The push is `git push --no-verify` of the same SHA, since the
  hook has run. If origin moved in between, git refuses it as not a
  fast-forward.
- **`PUSH_FAILED`.** Its detail is `git push exited <code>`, with the
  meaning of exit 141 (the connection to the remote closed), followed only by
  git's and the transport's own lines (`error:`, `fatal:`, `remote:`, `To`,
  `ssh:`, ` ! `, `Connection to … closed`). Before, it repeated the last 20
  lines of the push's whole output, the hook's included.
- **Exit.** Exit 2 (`ERROR`) covers a failed gate as well as a failed push.

`atc doctor` (ATC-0064):

- **`atc environment` line.** `atc doctor` adds a check of the processes,
  itself and its ancestors excepted, whose command line runs from the
  installed `atc` environment. `READY` when there are none. Otherwise `WARN`
  with `ATC_ENV_IN_USE: <n> processes run from <prefix>; uv tool install
  fails until they end`, followed by one `atc environment process` `WARN`
  line per process with its PID and command. A host whose processes cannot
  be listed gets a `WARN` asking for a check by hand.

The integration record (ATC-0062):

- **Schema follows the report.** A record that wraps an
  `atc-verification-report/2` or `/1` report has the schema
  `atc-verification-evidence/2`, the format that report's gate reads, with no
  `reused`. atc 0.8.0 stamped every record `/3`, which the gate of a project
  on an earlier testkit refused with `SCHEMA_MISMATCH`, so that project ran
  its tests at every push. A record wrapping a `/3` report stays `/3`
  (`shared/conformance/verification-evidence/README.md` § Record).

ATC-managed paths (ATC-0062, testkit 0.16.0):

- **`atc_testkit.managed`** is new and is the one definition of a file ATC
  manages in a project: a file under `.atc/` outside `.atc/tasks/`, a task
  record `.atc/tasks/<name>.yaml`, and a file of `<dir>/skills/<name>/`
  whose `SKILL.md` frontmatter carries `managed-by: agent-traffic-control`
  (`docs/TESTKIT.md` § ATC-managed paths).
- **Selection.** The shared selector classifies a managed path before every
  other rule and selects only the tests that name the file, with the reason
  `ATC-managed, named by tests` or `ATC-managed, not a test input`.
  `SelectionPolicy` adds `root`, the repository whose skill copies are read;
  without it only the path rules apply.
- **Verifier.** It counts a managed path as documentation-only and outside
  the input set. `atc_testkit.verifier.is_atc_managed` is removed; its
  replacement is `atc_testkit.managed.is_managed`. The keyword argument
  `managed` of `atc_testkit.verifier.documentation_only` is renamed `owned`.
- **Manifest rule.** A project's `owned` manifest target lies under `.atc/`,
  outside `.atc/tasks/`; another target is an invalid manifest.

Input evidence (ATC-0066, ATC-0068, testkit 0.16.0):

- **`ATC_FILE_OUTCOMES`** is removed from the isolated environment of every
  process the gate, the verifier and `atc test` start, so a run nested under
  one that records input evidence never writes into the outer run's outcomes
  file. The verifier sets it only for the stages whose evidence it records.
- **Non-Python toolchain.** The verifier prints
  `input evidence: not used by the <toolchain> toolchain` before running
  such a toolchain's stages whole.
- **Conformance.** The input evidence record format, `atc-input-evidence/1`,
  its identity, lookup, coverage and retention, is now a conformance contract
  in `shared/conformance/verification-evidence/README.md` § Input evidence,
  moved there from `docs/TESTKIT.md` unchanged.

Host workers (ATC-0063, testkit 0.16.0):

- **Nested run.** A run is also nested, and waits on no pool, when a live
  ledger row of its pool that holds tokens belongs to its own process or an
  ancestor, whatever its environment. A verifier that a project's tests call
  in process with an environment they build, under a run holding the pool's
  tokens, no longer waits on its ancestor's tokens forever. On Windows the
  ancestor walk stops at a parent created after its child.

Link check (ATC-0060, testkit 0.16.0):

- **Linked images.** `atc_testkit.docs` also checks the target of a link
  whose text is an image, such as a badge, where it checked only the image's
  own target. A broken badge link is now a finding.

Documents and skills (ATC-0068, ATC-0064):

- **Moved to `docs/development/`.** The maintainer sections and
  paragraphs of `docs/TESTKIT.md`, `docs/ATC_HOME.md` and `docs/WORKFLOW.md`
  are maintainer documents: `TESTING.md` (the workspace root's verifier,
  formerly `docs/TESTKIT.md` § The workspace root's verifier, and
  `check.ps1`), `TESTKIT_INTERNALS.md` (packaging, the input evidence
  internals, the line recorder), `DOCS_SITE.md` (building the docs site) and
  `RELEASING.md` (cutting a release). A citation of a moved section names
  its new file.
- **Skills.** `atc-coordinator`, `atc-review` and `atc-worktree` name each
  step and leave its flags to the command's `-h`: the restated forms of
  `atc task create`, `update`, `list` and `close`, `atc test --mutants`,
  `--lint` and `--candidate`, and the mutants file's shape are removed from
  the skills. The skills' contracts are unchanged.

## atc-testkit 0.16.0

A project vendors one testkit wheel (`vendor/atc-testkit.json`) and keeps it
until it upgrades. `atc test` runs from the atc-testkit that installs with
`atc`; the project's verifier and pre-push gate run from its vendored one.

| Change | Runs from | Project upgrade |
| --- | --- | --- |
| ATC-managed paths from what sync writes: selection, `SelectionPolicy.root`, documentation-only (ATC-0062) | the project's vendored testkit (gate selection, verifier) | skippable, at a cost: on 0.15.0 or earlier a sync commit's paths that the project's own list does not name, such as `.atc/lint/` files, fall to `no selection rule -> full suite` at the gate and count as the verifier's inputs. Upgrading requires passing `root` to the project's `SelectionPolicy` and removing its own list of ATC-written files (hami-quant-trading's and hami-quant's `atc_owned()`), and a caller of `verifier.is_atc_managed` or `documentation_only(managed=...)` moves to `managed.is_managed` and `owned=` |
| Stage-time record fields, the gate's `prepush` records, `ATC_PROJECT` and `ATC_VERSION` (ATC-0063) | the installed `atc` (`atc test`, `atc test --timings`); the project's vendored testkit (verifier, gate) | skippable, at a cost: an older verifier writes records without the new fields, which `atc test --timings` shows as `-` and attributes by the task's prefix, and an older gate writes none, so a push's test time leaves no record |
| A run nested by its ancestor's pool tokens (ATC-0063) | the installed `atc` (`atc test`); the project's vendored testkit (verifier, gate) | skippable, at a cost: a project whose tests run its verifier in process under a run holding the pool's tokens, such as hami-quant-trading's tests under `ci --stages`, can wait forever on its own ancestor's tokens until it upgrades |
| `ATC_FILE_OUTCOMES` dropped from stage environments; the non-Python toolchain note (ATC-0066) | the installed `atc` (`atc test`); the project's vendored testkit (verifier, gate) | skippable: an older verifier nested under a run that records evidence can write its stage outcomes into the outer run's file, which the outer run rewrites last; a non-Python toolchain runs its stages whole without the note |
| `atc_testkit.docs` checks a linked image's link target (ATC-0060) | the project's vendored testkit (its link hook) | skippable: an older testkit leaves a badge's link target unchecked. Upgrading can surface broken badge links as findings |
| `atc test ID -- ARGS` is an explicit run (ATC-0067) | the installed `atc` | skippable: none. Once the host installs 0.9.0, hami-quant-trading's `atc test ID --all -- <files>` workaround is no longer needed: `atc test ID -- <files>` runs the files, with no testkit upgrade |
| `atc integrate` progress and live verifier log; `--candidate` drops the repeated `ELAPSED` lines (ATC-0063) | the installed `atc` | skippable: none |
| `atc push` gate step, `GATE_FAILED`, `PUSH_FAILED` detail (ATC-0063) | the installed `atc`, which runs the project's own hook | skippable: none |
| An integration record's schema follows the report it wraps (ATC-0062) | the installed `atc` | skippable: none. A project on an earlier testkit gains its gate's reuse of integration records again |
| `atc doctor`'s `atc environment` line (ATC-0064) | the installed `atc` | skippable: none |

`min_atc` in `atc-manifest.yaml` stays 0.8.0. atc-testkit 0.16.0 writes the
same `atc-verification-report/3` and evidence formats as 0.15.0, which atc
0.8.0 reads, and its new stage-time fields and inputs are optional: under
atc 0.8.0 a record takes its project from the checkout's directory and an
empty `atc_version`.

## First run

The docs site's generator, Zensical, joins the workspace root's development
environment (`adapters/python` dependency group `site`), so the first
`uv run --locked` in a root worktree after this release downloads it.
`docs/TESTKIT.md` records no figure for it. It is not part of the installed
`atc`, and projects do not install it.

## Upgrade

The Owner's steps on each host, in this order:

1. Run no `atc test`, verifier or other `atc` command while uv replaces `atc`: `atc doctor`
   reports its `atc environment` line READY. On Windows, rerun the install after a `WinError 32`.
   The `atc doctor` of atc 0.8.0 has no such line, so before this install
   the Owner checks by hand that no `atc` process runs.
2. On a host that did not create `v0.9.0`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host installs
   from GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.9.0#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.9.0#subdirectory=adapters/python"
   ```

4. From the Owner's own terminal, one command per line:

   ```text
   atc sync --check
   atc sync
   atc doctor
   ```

   The hook table is unchanged since 0.7.0, so `atc guard --install` is not
   rerun. `atc doctor` reports `atc 0.9.0` at `v0.9.0` with its commit and
   its `atc environment` line, and exits 0 once every check is READY, WARN or
   NOT_INITIALIZED.
5. Replace changed names in scripts and briefs:
   - an explicit test list run as `atc test ID --all -- <files>` becomes
     `atc test ID -- <files>`;
   - a script that read the `ELAPSED` lines from the stdout of
     `atc test ID --candidate` reads them from stderr or the verifier's log;
   - a script that parsed `PUSH_FAILED`'s last 20 lines reads git's own
     lines, and one that matched a hook failure under `PUSH_FAILED` matches
     `GATE_FAILED`;
   - a citation of a section moved to `docs/development/` names its new
     file (§ Breaking, Documents and skills).

### Projects

Re-sync on 0.9.0 (`atc sync <project>`, or `atc sync` for all). Until a
project's `.atc/atc.lock` pins v0.9.0, the task flow stops there with
`STOP RELEASE_MISMATCH`. The re-sync delivers the skill copies that leave CLI
flags to `-h`. A project keeps its vendored testkit through the re-sync.

Upgrading a project's vendored atc-testkit to 0.16.0 goes through
Hami-Coordinator. This version's delta for a project that upgrades:

- pass `root` to the project's `SelectionPolicy` and remove its own list of
  files ATC writes (hami-quant-trading's and hami-quant's `atc_owned()`);
  `<gate> --paths` for the paths of a sync commit then prints `ATC-managed`
  for each;
- move a caller of `atc_testkit.verifier.is_atc_managed` to
  `atc_testkit.managed.is_managed`, and a keyword call
  `documentation_only(..., managed=...)` to `owned=`;
- expect the link hook to report broken badge link targets.

A project that upgrades its
vendored atc-testkit follows [Upgrading a project's testkit](../TESTKIT.md#upgrading-a-projects-testkit).
