atc 0.10.1 (atc-testkit 0.17.0)

atc 0.10.1 fixes `atc sync` on a release that changes no file sync writes.
On atc 0.10.0 sync moved a project's `.atc/atc.lock` only together with a
synced file, and 0.10.0 changes none, so `atc sync --check` reported every
project `current` while `atc doctor` and every task-flow command reported
`RELEASE_MISMATCH` (`pins v0.9.0 ... the installed atc is v0.10.0`) with the
hint `atc sync <project>`, which then changed nothing. Sync now moves the
lock to its target whenever the locked revision differs, with no file
change, and never moves a project back from a pin ahead of the installed
release without `--revision`.

## Breaking

The lock follows the sync target (ATC-0075):

- **`atc sync --check`.** A project whose lock pins another revision than
  the target, with every synced file current, reports `~1` for
  `.atc/atc.lock` and the run exits 1 with `STOP DRIFT`. Before, it reported
  the project `current` and exited 0.
- **`atc sync`.** It commits such a project with a sync commit that changes
  `.atc/atc.lock` alone. Before, it wrote nothing.
- **`atc add`.** Adding a repository whose lock pins another revision than
  the target lists the lock as an update and stops, as it does for any file
  it would update; `atc sync <project>` then moves it.

A project locked ahead of the target is unchanged: sync reports it
`current (locked at <sha>, ahead of <tag>; ...)` and writes nothing.

## Tasks

- ATC-0075: `atc sync` moves a project's lock to the installed release
  when no synced file changes, which clears the `RELEASE_MISMATCH` every
  project hit after installing 0.10.0; this release.

## Upgrade

The Owner's steps on each host, in this order:

1. Run no `atc test`, verifier or other `atc` command while uv replaces `atc`: `atc doctor`
   reports its `atc environment` line READY. On Windows, rerun the install after a `WinError 32`.
2. On a host that did not create `v0.10.1`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host installs
   from GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.10.1#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.10.1#subdirectory=adapters/python"
   ```

4. From the Owner's own terminal, one command per line:

   ```text
   atc sync --check
   atc sync
   atc doctor
   ```

   `atc sync --check` lists each project pinned to an older release with
   `~1` and stops with `STOP DRIFT`; `atc sync` then moves each pin. The hook
   table is unchanged since 0.7.0, so `atc guard --install` is not rerun.
   `atc doctor` reports `atc 0.10.1` at `v0.10.1` with its commit, and exits
   0 once every check is READY, WARN or NOT_INITIALIZED.

### Projects

Re-sync on 0.10.1 (`atc sync <project>`, or `atc sync` for all). Each
project pinned to v0.9.0 gets one sync commit that changes `.atc/atc.lock`
alone, to v0.10.1; until then its task flow stops with
`STOP RELEASE_MISMATCH`. No skill, governance rule, lint rule or testkit
changed since 0.10.0, so a project keeps its vendored testkit. The 0.10.0
steps for projects that hold `.pre-commit-config.yaml` (§ Projects of
`docs/releases/v0.10.0.md`) apply from this install on.

A project that upgrades its
vendored atc-testkit follows [Upgrading a project's testkit](../TESTKIT.md#upgrading-a-projects-testkit).
