atc 0.12.0 (atc-testkit 0.18.0)

atc 0.12.0 widens the related tests of `atc test ID` in two ways. A
project can declare, in `[tool.atc-testkit.dependents]`, the tests that read
files without importing them; `atc test ID`, the pre-push gate and the
verifier run them when such a file changes, and a pattern that no longer
matches a file stops the run. A project with no `selector` gets an import
edge from the testkit itself, so its related run and its mutant selection
take the test files that import a changed module, not only the changed test
files. `atc task close` lists more hand-named scratches for the Owner's
consent, a `TESTS_UNAVAILABLE` refusal names the brief that set the level,
and the `atc-coordinator` skill's close-out steps are corrected. No command,
flag, token or exit code is removed.

## Breaking

No command, flag, output token, exit code, record field, skill contract or
governance rule is removed or renamed. These outputs and behaviours change:

Related tests in a project without `selector` (ATC-0086, testkit 0.18.0):

- **Selection.** `atc test ID` in a test directory whose
  `[tool.atc-testkit]` has no `selector` key runs the changed test files and
  the test files that import a changed module (`docs/TESTKIT.md` § Default
  import edge). Before, it ran the changed test files alone. Its related runs
  grow accordingly; hami-quant and hami-quant-trading declare no `selector`.
- **Full suite on a root `conftest.py`.** A changed `conftest.py` at the
  test directory, or a module it imports or names in `pytest_plugins`, makes
  the related run the full suite, with the line
  `FULL conftest.py at the tree root` and a `RELATED` line that reads
  `<n> changed paths, all test paths`. A script that reads `<k>` of
  `RELATED <base>: <n> changed paths, <k> test paths` as a number meets
  `all`. A changed `conftest.py` below it selects its directory.
- **New lines.** `SELECTOR default import edge` before the selection, and
  `UNPARSED <test path>` for a test file the testkit's interpreter cannot
  parse, which is selected.
- **Mutants.** `atc test ID --mutants` in such a project gives each mutant
  the test files the edge selects, before its own `tests`; a mutant that
  named none no longer stops with `NO_TESTS` when the edge selects one. The
  `NO_TESTS` detail reads `the selection picks none` (was
  `the selector picks none`).

Declared dependents (ATC-0084, testkit 0.18.0):

- **New refusals.** A `[tool.atc-testkit.dependents]` table that breaks
  `docs/TESTKIT.md` § Declared dependents stops `atc test ID` (every form),
  the gate and the verifier with `ATC_CONFIG_INVALID` (exit 9), and
  `atc_testkit.check` reports it; one of them is a pattern that matches no
  file, so a rename stops the next run until the declaration follows it. A
  project that declares nothing meets none of them.
- **New output.** `DECLARED <test path> <- <changed path>` (`(+<m> more)`
  when several match) before the `RELATED` line, whose `<k>` counts them. The
  stage-time `selection_reason` of a related run reads
  `<n> changed paths, <d> declared` when `<d>` is above 0; the verifier's and
  the gate's targeted reasons gain `<path>: declared dependent <key>` lines.
- **testkit API.** `atc_testkit.testrun.touched` returns an
  `atc_testkit.import_edge.Edge` (`tests`, `full`, `notes`) instead of a
  list of paths. A `Project`'s `select` is wrapped to add the declared
  dependents through the new `Selection.declare`.

`TESTS_UNAVAILABLE` (ATC-0085): when the level came from a brief's
`## Tests`, the detail adds `; the brief's ## Tests names <level> (<brief>)`
and the hint reads `remove the brief's ## Tests section or set it to none`
(was `pass --tests none`, which stays the hint otherwise). The token and
exit code are unchanged.

`atc task close` (ATC-0080): an unregistered directory under `<tmp>` counts
as named for the task when its name starts with the task ID compared without
case and with `-` and `_` skipped (`hqt0062-probe`, `HQT_0062` for
`HQT-0062`), so close-out lists more directories for the Owner's consent.
It still deletes none of them.

## atc-testkit 0.18.0

A project vendors one testkit wheel (`vendor/atc-testkit.json`) and keeps it
until it upgrades. `atc test` runs from the atc-testkit that installs with
`atc`; the project's verifier, pre-push gate and contract check run from its
vendored one. The projects vendor 0.15.0, so an upgrade to 0.18.0 also takes
the 0.16.0 rows of `docs/releases/v0.9.0.md` and the 0.17.0 rows of
`docs/releases/v0.10.0.md`.

| Change | Runs from | Project upgrade |
| --- | --- | --- |
| Declared dependents in `[tool.atc-testkit.dependents]`, merged with the related run's test paths, and the refusal of an invalid or stale declaration (ATC-0084) | the installed `atc` (`atc test ID`, every form); the project's vendored testkit (pre-push gate, verifier, `atc_testkit.check`) | required for a project that declares dependents, such as hami-quant-trading's declaration of `scripts/tests/test_mutation_targets.py`. Once the host installs 0.12.0, `atc test ID` reads and checks the declaration whatever testkit the project vendors; a testkit older than 0.18.0 ignores the table, so its gate and verifier run no declared test outside the full suite and its contract check lets a stale pattern through. A project that declares nothing loses nothing by skipping |
| The default import edge for a test directory with no `selector` (ATC-0086) | the installed `atc` (`atc test ID` related runs, `atc test ID --mutants`) | skippable, nothing lost: the gate and the verifier do not use it. hami-quant-trading's ledger tests, which import a changed `ledger.py`, are selected by `atc test ID` once the host installs 0.12.0, with no project change |

`min_atc` in `atc-manifest.yaml` stays 0.8.0. atc-testkit 0.18.0 writes the
same `atc-verification-report/3`, evidence and stage-time formats as 0.17.0,
and `selection_reason` stays a free-text field that atc 0.8.0 reads.

## Upgrade

The Owner's steps on each host, in this order:

1. Run no `atc test`, verifier or other `atc` command while uv replaces `atc`: `atc doctor`
   reports its `atc environment` line READY. On Windows, rerun the install after a `WinError 32`.
2. On a host that did not create `v0.12.0`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host installs
   from GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.12.0#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.12.0#subdirectory=adapters/python"
   ```

4. From the Owner's own terminal, one command per line:

   ```text
   atc sync --check
   atc sync
   atc doctor
   ```

   The hook table is unchanged since 0.11.0, so `atc guard --install` is not
   rerun. `atc sync --check` lists each project pinned to an older release
   and stops with `STOP DRIFT`; `atc sync` then moves each pin with the
   updated `atc-coordinator` skill. `atc doctor` reports `atc 0.12.0` at
   `v0.12.0` with its commit, and exits 0 once every check is READY, WARN or
   NOT_INITIALIZED.

### Projects

Re-sync on 0.12.0 (`atc sync <project>`, or `atc sync` for all): each
project gets the updated `atc-coordinator` skill and its lock at v0.12.0;
until then its task flow stops with `STOP RELEASE_MISMATCH`.

With no testkit upgrade, a project without `selector` (hami-quant,
hami-quant-trading) gets the default import edge in `atc test ID` and
`atc test ID --mutants` as soon as the host runs 0.12.0: related runs grow,
and a change to the tree-root `conftest.py` or a module it loads runs the
full suite (for hami-quant-trading, `conftest.py`, `scripts/tests/tk_window_events.py`
and `scripts/tests/tk_root_guard.py`). A project that adds
`[tool.atc-testkit.dependents]` upgrades its vendored testkit to 0.18.0 in
the same task, so its gate and verifier select the declared tests and its
contract check refuses a stale pattern; from 0.15.0 that upgrade also takes
the 0.16.0 and 0.17.0 deltas.

A project that upgrades its
vendored atc-testkit follows [Upgrading a project's testkit](../TESTKIT.md#upgrading-a-projects-testkit).
