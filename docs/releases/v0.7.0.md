atc 0.7.0 (atc-testkit 0.14.0)

atc 0.7.0 is installed with `uv tool install` from its tag: the Owner runs it,
`atc` never installs itself, and uv records the installed commit in the
distribution's `direct_url.json`, which the release pin, `atc sync` and
`atc doctor` read. `atc install` and the release copies under
`~/.atc/releases` are gone. A workspace is any directory that holds
`workspace.yaml`, and `atc sync` delivers what the revision's
`atc-manifest.yaml` names, read from Git objects. The PreToolUse hook is
`atc hook`: it composes its own table from the `main` of the workspace root
and every registered project, so `atc guard --install` runs once per host and
a policy change, an `atc add` or a new install needs no rerun. `atc doctor`
names an installed `atc` older than `main` first, and a NOTE under that line
exits 1. `atc test ID --mutants` shards its baseline over the host's workers,
reuses it on the same tree, and judges each mutant by the baseline tests that
ran the lines it edits. Every `atc test` stage prints its elapsed time and
appends it to `timings.jsonl`. Removed and renamed names keep no alias: the
old spelling is a usage error.

## Breaking

Installing `atc` and finding the workspace (ATC-0049):

- `atc install TAG [--check] [--json]` is removed, with `~/.atc/releases`
  and every release copy reader; an existing `~/.atc/releases` is unused. The
  Owner installs and upgrades with
  `uv tool install --force "git+<source>@<tag>#subdirectory=adapters/python"`
  (`docs/WORKFLOW.md` § Installing a release). The hard-deny rule
  `atc-install` is removed; installing `atc` is the Owner's act by
  documentation, and agents cannot run `uv tool install|upgrade|uninstall`
  (ATC-0053).
- The installed release is the commit in `direct_url.json`. An `atc` that
  records no commit (`uv run atc` in a topic worktree, an editable or local
  install) has no installed release, so no project pin is compared. The
  `RELEASE_MISMATCH` hint, `atc doctor` and `atc init`'s PATH hint name
  `uv tool install`, not `atc install`.
- A workspace directory is any directory that holds `workspace.yaml`:
  `--root`, `ATC_ROOT`, else the nearest parent of the working directory.
  `shared/governance/` is no longer required and there is no fallback to the
  checkout the code comes from. Outside a workspace a command stops with
  `STOP WORKSPACE_NOT_FOUND` (exit 1); `atc init` creates the workspace in the
  working directory, `atc doctor` reports it, `--help` works.
- The canonical checkout guard (`CHECKOUT_NOT_MAIN`, `CHECKOUT_DIRTY`,
  `CHECKOUT_UNREADABLE`) applies only when the workspace directory is the
  governance checkout: `workspace.yaml` names `governance_checkout: .`, or the
  directory is a Git top level holding `atc-manifest.yaml`. `root` names
  `governance_checkout`, else the workspace directory. A workspace directory
  that is the ATC checkout but does not say so stops `atc sync` and `atc add`
  with `GOVERNANCE_CHECKOUT_UNSET`, is an ERROR in `atc doctor`, and makes the
  hook deny every call with the same token; the fix is
  `governance_checkout: .` in `workspace.yaml`.
- `atc-maintain` runs only as an editable install of an ATC checkout, and
  stops with `CHECKOUT_CANONICAL` in the canonical checkout and when run from
  a wheel.
- The modules `atc` and `atc-maintain` run moved from
  `adapters/python/scripts/` to `adapters/python/src/atc_cli/scripts/`, with a
  copy of `shared/policies/schemas/` in `src/atc_cli/schemas/`, so the wheel
  carries both. A script path under `adapters/python/scripts/` in a project's
  CI or tooling becomes `src/atc_cli/scripts/<name>.py`; the integration
  verifier, its argv file `adapters/python/scripts/integration-verify.json`,
  `select_tests.py` and `build_testkit_release.py` stay in `scripts/`.

Sync (ATC-0049):

- `atc sync`, `atc sync --check`, `atc add` and `atc add --skill` deliver what
  `atc-manifest.yaml` names, read from the Git objects of the revision in the
  content repository: `governance_checkout`, else the bare cache
  `~/.atc/content/<owner>/<repo>.git` of `governance_source`. A revision
  without a manifest, every tag before v0.7.0, is refused with `NO_MANIFEST`,
  also for a SHA the Owner names with `--revision`; `MANIFEST_INVALID`,
  `MANIFEST_SOURCE_MISSING` and `MANIFEST_TOO_NEW` (the running `atc` is older
  than the manifest's `min_atc`) stop it too. `atc doctor` reads the cache
  without fetching; a cache not yet fetched is a WARN (`CONTENT_CACHE_MISSING`).
- `atc add` checks the content repository before it clones or registers.
- Where the workspace directory is the governance checkout, sync renders
  nothing until that checkout is on `main`, has no tracked change and its
  adapters match the tip of `main`; elsewhere it delivers the manifest's
  `workspace` items (`GIT_WORKFLOW.md` § Governance sync commits).
- New commands: `atc checkout` makes a clean, detached tree of a project at a
  commit on its `main` for a build; `atc hook` is the command a hook entry
  runs.

The PreToolUse hook, `atc guard` and `atc doctor` (ATC-0049, ATC-0053):

- The hook entry is `atc hook --harness H --workspace MAP --home DIR
  --atc-home DIR`. `atc guard --install` replaces an entry that runs an engine
  by path (the 0.6.0 form) and the retired guards; Codex asks the Owner to
  trust the new entry once in `/hooks`. The hook table write-protects uv's
  tool environment of `atc`, no longer `~/.atc/releases`.
- The hook composes its table from reviewed inputs: `policies/hard-deny.yaml`
  at the `refs/heads/main` of the workspace root (`governance_checkout`, else
  the workspace's own file) and of every registered project, plus the map.
  A policy edit in a worktree, or uncommitted, never reaches it; one takes
  effect once it is on `main`. The table is cached under
  `~/.atc/enforcement/` and only tightens automatically.
- `atc guard --install` writes the baseline (`baseline-<m>.json`) and the
  entries, once per host; it no longer writes the table
  `~/.atc/enforcement/pretooluse.json`. New: `atc guard --reset`, the Owner's
  one way to loosen the table; it also deletes a legacy `pretooluse.json`.
  Bare `atc guard` reports the entries, the baseline, whether the table
  composes, what is retained and a legacy table. A table that cannot be
  composed denies every call with `Refused: the PreToolUse hook cannot compose
  its table: <TOKEN>` (tokens in `docs/ENFORCEMENT.md`); a missing baseline is
  `BASELINE_MISSING` until `atc guard --reset`.
- Bare `atc guard` no longer refuses with `GUARD_NOT_INSTALLED` (no table
  file) or `GUARD_DRIFT`, and its `--json` has no `drift` list. It stops with
  `ENTRY_<STATE>` (`ENTRY_MISSING` and the other states of a hook entry that
  is not current), else the baseline's token (`BASELINE_MISSING`,
  `BASELINE_INVALID`; the fix is `atc guard --reset`), else the token of a
  table that does not compose. Its `--json` carries `entries`, `baseline`,
  `table`, `retained` and `legacy`, with `verdict: CURRENT`.
- `atc guard --install` prints `INSTALLED guard (baseline and N hook
  entries; ...)` (was `table and N hook entries`), and its `--json` names the
  `baseline` file where it named `hook_table`. `--reset` prints
  `RESET guard (N rules dropped)`, and `--json` `PLANNED` or `RESET`; both
  are new, as are the refusals `REPLACE_REFS_PRESENT`, `ALTERNATES_PRESENT`
  and `MAIN_DIVERGED`.
- `atc doctor` check names (text and `--json`): `atc install` is now
  `installed atc`; `pretooluse hook` is split into `pretooluse entries`,
  `pretooluse baseline`, `pretooluse table` and `pretooluse retained`
  (`pretooluse legacy` is new). A script keyed on a check name changes.
- The `atc install` refusals `TAG_INVALID`, `TAG_UNKNOWN`,
  `TAG_NOT_ON_MAIN`, `ROOT_NOT_MAIN_WORKTREE`, `RELEASE_COPY_INVALID`,
  `UV_MISSING` and `COPY_FAILED` leave with the command; `uv tool install`
  reports its own errors.
- The deny text of a payload the hook cannot decide names `atc doctor` (was
  `atc guard --install`); the conformance cases `payload-not-json` and
  `table-wrong-version` expect it.
- `atc doctor` compares the installed `atc` with the workspace `main` first,
  one root line `installed atc`: `ATC_NOT_ON_MAIN`, `ATC_BELOW_MIN` and
  `ATC_BEHIND_RELEASE` are ERROR, `ATC_BEHIND_MAIN` and `ATC_SKEW_UNKNOWN` are
  WARN. Under an ERROR skew, the checks that follow from it (workspace-managed
  adapters, a project's integration or testkit, a pin ahead of the installed
  release) are listed as `NOTE` beneath it.
- **BREAKING, exit code:** `atc doctor` has a new status `NOTE`, and a NOTE
  exits 1 like an ERROR: exit 0 only when every check is READY, WARN or
  NOT_INITIALIZED. Its summary line ends `N note(s)`, and `--json` carries
  `notes` and `verdict: NOT_READY`, with `follows: installed atc` on a NOTE.
  A script that read exit 0 from a skewed host as ready now reads 1; install
  the release the root line names.
- Hard-deny (`policies/hard-deny.yaml`): `atc-install` is removed;
  `atc-guard-install` becomes `atc-guard-install-reset` (`atc guard --install`
  and `--reset`); new `atc-hook-workspace`, `atc-init-force`,
  `uv-tool-install`, `uv-tool-upgrade`, `uv-tool-uninstall`. uv's global
  options before the subcommand are dropped before matching.
- A PowerShell write to `env:`, `Cert:`, `WSMan:`, a registry drive or any
  provider but the file system is no write target and passes (ATC-0053).

`atc test` (ATC-0051, ATC-0052, ATC-0054, ATC-0055):

- `atc test ID`, `--all`, a `--sha` export and `--mutants` run in the
  verifier's isolated environment: `HOME` and `USERPROFILE` name
  `<scratch>/home`, the uv, Python and ruff caches are those under
  `~/.atc/cache`, and the project's `credential_variables` are removed. A test
  that read the host's home now sees an empty one (ATC-0052).
- Output: `atc test ID` prints `ELAPSED <stage> <seconds>s workers <n>
  <result>` just before its summary line, a mutant run before each verdict
  line, and the verifier into its log; `atc test ID --candidate` repeats them
  before `PASS candidate <sha> FF|NO_FF`, which stays the last line. Each is
  one record in `timings.jsonl` of the host pool directory (ATC-0051).
- `atc test ID --mutants FILE` without `-- TEST...` judges each mutant by the
  tests the tree's `selector` picks for the paths it edits plus its own
  `tests`, not by every related test; `NO_TESTS` stops a mutant the selector
  gives nothing, before the baseline (ATC-0052). The baseline records the
  lines each test executes, and a mutant then runs only the baseline tests
  that executed a line it edits. A mutant no test reaches prints
  `NOT_COVERED <label> -> no baseline test runs <path>:<lines>` without a run,
  counts as a survivor in the `done:` line and exits 1; a file the recorder
  could not observe falls back to its file-level tests with a `NOTE` line
  (ATC-0054). `-- TEST...` still judges every mutant.
- The mutants baseline runs sharded on the workers `atc test ID` would take,
  then gives back all but one token, held to the end (was one token for the
  whole command). A later run on the same tree, tests, recorder and testkit
  reuses it and prints `BASELINE-OK reused ...`; `BASELINE-RED` names every
  failed test. One run holds a scratch at a time: another stops with
  `MUTANTS_RUNNING` (exit 9), a mutated tree with `TREE_NOT_PRISTINE`
  (exit 9), and `atc test ID --clean` refuses a scratch a run holds
  (ATC-0055).
- `atc task close ID`, and its `--check` rehearsal, delete a scratch whose
  links (junctions, symlinks) all resolve inside it, removing each as a link;
  a scratch with any link out of it is REFUSED with that link named
  (ATC-0052).
- This repository's test selector (`select_tests.py`) tells a function-level
  import from a top-level one and counts a name a file declares as data as no
  edge (`pretooluse_hook.py` declares `atc_cli`), so a change to `atc_cli`
  selects fewer tests than the full suite; the full suite is the
  Owner-dispatched CI run (ATC-0051).

Skills and governance:

- `VERIFICATION.md` § Test levels (ATC-0053): under `strict` the reviewer
  writes and runs the mutants; the writer writes and runs none, and its step
  report lists the guards the change adds or alters, each as `file:line` and
  what it blocks. `atc-review` and the `atc-coordinator` brief follow, and the
  reviewer brief carries a fixed 30-minute mutant-run budget.
- `GIT_WORKFLOW.md` § Explicitly authorized squash (ATC-0052): the squash
  commit message no longer has to carry the source tip SHA. § Governance sync
  commits names the Git objects and the `governance_checkout` (ATC-0049).
- `atc-coordinator` is model-invocable (`invocation: user` is gone), re-reads
  itself and `atc-review` after a compaction, and stops each reviewer
  subagent of a task at close-out (ATC-0052, ATC-0055). `atc-review`: a
  session is titled `[<task ID>] <topic>`; a step report and a verdict are
  files in `~/.atc/reports/` named with the full 40-character SHA, never the
  notes folder; a task whose deliverable is a report commits it as
  `docs/design/<ID>.md` or sets `keep: reports`; a reviewer, a subagent
  included, writes its own files only inside a scratch registered to the task
  (ATC-0052, ATC-0053, ATC-0054).
- `atc-worktree` names `uv tool install` where it named `atc install`
  (ATC-0049); its machine contract is unchanged.

## atc-testkit 0.14.0

A project vendors one testkit wheel (`vendor/atc-testkit.json`) and keeps it
until it upgrades. `atc test` runs from the atc-testkit that installs with
`atc`, so every change below that is marked skippable reaches a project with
the installed `atc` alone.

| Change | Runs from | Project upgrade |
| --- | --- | --- |
| `atc test ID` isolated environment, `--mutants` selection, line recorder, `NOT_COVERED`, sharded and reused baseline, `MUTANTS_RUNNING`, `TREE_NOT_PRISTINE`, scratch lock (ATC-0052, ATC-0054, ATC-0055) | the installed `atc` | skippable: none |
| Stage times: the project's verifier and its static-check stage print `ELAPSED` lines and append `timings.jsonl`; the optional input `ATC_TASK` names the task (ATC-0051) | the project's vendored testkit | skippable: an older verifier prints no `ELAPSED` lines and records nothing, `atc test ID --candidate` repeats what it prints, and `ATC_TASK` is optional |
| `credential_variables` of `[tool.atc-testkit]` read by `atc test ID` (ATC-0052) | the installed `atc` | skippable: the key keeps its meaning |

No evidence record, report or `vendor/atc-testkit.json` field changes, so
evidence written by 0.13.0 and by 0.14.0 compares the same and a project on
0.13.0 passes `atc doctor`'s testkit check. A project that wants stage times in
its own verifier upgrades by the steps in `adapters/python/atc-testkit/README.md`
(build the wheel from the tag, commit it under `vendor/`, pin
`atc-testkit==0.14.0`).

## Upgrade

The Owner's steps on each host, in this order:

1. Leave no task worktree open in any project (`atc task close ID`), and run
   no session while uv replaces `atc.exe`; on Windows rerun the install after
   a `WinError 32`.
2. On a host that did not create `v0.7.0`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. On the host whose workspace directory is the ATC checkout, add
   `governance_checkout: .` to its `workspace.yaml` first. Without it
   `atc sync` and `atc add` stop with `GOVERNANCE_CHECKOUT_UNSET`.
4. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host from
   GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.7.0#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.7.0#subdirectory=adapters/python"
   ```

5. From the Owner's own terminal, one command per line:

   ```text
   atc guard --install
   atc sync --check
   atc sync
   atc doctor
   ```

   `atc doctor` reads `direct_url.json` and reports `atc 0.7.0` at `v0.7.0`
   with its commit; it exits 0 once every check is READY, WARN or
   NOT_INITIALIZED.
6. Codex asks the Owner to trust the new hook entry once in `/hooks`.
7. Replace removed names in project scripts, CI and integration verifier argv
   files: `atc install` becomes `uv tool install`, a script path under
   `adapters/python/scripts/` becomes `src/atc_cli/scripts/`, and a check
   that read `atc doctor` exit 0 as ready counts NOTE lines too.

Projects: re-sync on 0.7.0 (`atc sync <project>`, or `atc sync` for all). Until a
project's `.atc/atc.lock` pins v0.7.0 the task flow stops there with
`STOP RELEASE_MISMATCH`. Upgrading a project's vendored atc-testkit is
skippable (§ atc-testkit 0.14.0).
