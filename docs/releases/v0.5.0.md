atc 0.5.0 (atc-testkit 0.12.0)

atc 0.5.0 is the first release projects sync to by default: governance
resolves at the latest release tag, `atc onboard` renders that release
instead of the ATC checkout's `main`, and a release tag push drafts its GitHub
Release from these notes. It also brings one PreToolUse deny hook composed
from the hard-deny policies, PowerShell denies beside Bash denies,
`atc close-out --check`, `atc integrate --owner-run`, and the CLI
distribution renamed to `agent-traffic-control`. atc-testkit 0.12.0 runs tests
on the host's free workers by default with measured per-worker memory, and
`atc test run --task` registers a scratch under its task for close-out.

## Breaking

- Governance `CORE.md` § Effective authority and revocation: with no task
  revision and no project pin, governance resolves at the latest
  `vMAJOR.MINOR.PATCH` tag on the canonical branch, not its tip; an
  Owner-named SHA replaces the tag, a project's pin moves only by sync, and a
  task in the governance source binds its own `main`. The bootloader in
  `AGENTS.md` follows (ATC-0039).
- `atc onboard --check` and `--sync` (and `bootstrap add`) render and lock the
  latest release tag on `main` in the ATC checkout's local tags, or the SHA
  the Owner names with the new `--revision`; a project locked ahead of that
  release is skipped; `NO_RELEASE_TAG` and `REVISION_NOT_ON_MAIN` stop before
  any project. `atc validate --projects` compares a project's synced files
  with its locked revision's tree (ATC-0039).
- Governance `GIT_WORKFLOW.md` § Integrate: an agent may run `atc integrate`
  on the authority of a record on `main` granting `integrate_main`, after an
  unconditional PASS, where policy allows; while the workspace hard-deny
  policy denies agents `atc integrate`, the Owner runs every integration
  (ATC-0038).
- `atc enforce` renders one PreToolUse hook (`--hook-out`,
  `--install-hooks`, the Owner's) from the hard-deny policies, the new
  workspace `policies/hard-deny.yaml` and `agent_write_roots` in
  `workspace.yaml`; it absorbs the worktree cd guard and the write-scope
  guard (ATC-0038). Generated Claude settings carry a `PowerShell(...)` deny
  beside every `Bash(...)` deny (ATC-0036).
- Removed: the 0.1.0 layout's migrations. `onboard --sync`, `link-skills.sh`
  and `atc task new` no longer read or migrate `.atc/governance.yaml`, the
  `AGENTS.md` policy block or the old `CLAUDE.md` (ATC-0030).
- The CLI distribution is `agent-traffic-control` (was
  `atc-python-adapter`); the console script stays `atc`. Uninstall
  `atc-python-adapter` before installing (ATC-0031).
- atc-testkit: `atc test run` without `-n` takes the host's free workers,
  bounded by the pool and measured memory, instead of a fixed count (ATC-0023).

## Upgrade

- Reinstall `atc` on each host as `adapters/python/README.md` says; uninstall
  `atc-python-adapter` first if it is installed.
- Fetch the tags into the ATC checkout (`git fetch --tags`) on every host that
  did not create `v0.5.0`, then run `atc onboard --sync --all`.

## Assets

Verify the downloads with `sha256sum -c SHA256SUMS`.
