atc 0.6.0 (atc-testkit 0.13.0)

atc 0.6.0 is the first release a host installs from its tag: `atc install
TAG` makes `~/.atc/releases/<tag>` the code the host's `atc` and its
PreToolUse hook run, so integrating into `main` changes nothing a host runs
until the Owner installs a release, and the task flow stops on a project
whose `.atc/atc.lock` pins another release. It also redesigns the CLI around
the task ID. `atc task create` opens a
task's worktree, branch and record in one step, and every later command takes
that ID: `atc test ID`, `atc integrate ID`, `atc task close ID`. `atc push`
publishes `main` after checking every commit it carries, `atc sync` replaces
`atc onboard`, `atc init|add|remove` replace `atc bootstrap`, `atc guard`
installs the PreToolUse hook, and the maintainer commands move to
`atc-maintain`. A success prints one verdict line and a refusal a `hint:` line
with its fix. Task records carry a test level (`tests: none|standard|strict`).
The PreToolUse hook checks every PowerShell and shell write target it can
resolve and refuses one it cannot. atc-testkit 0.13.0 selects a task's related
tests from its base, ties every scratch to a task, runs mutants in the
scratch's own environment and refuses a mutants file of the wrong shape
before the baseline. Removed and renamed names keep no alias: the old
spelling is a usage error.

## Breaking

Installing a release (ATC-0048):

- The installed `atc` runs a release copy, `~/.atc/releases/<tag>`: a locked
  detached worktree of the workspace root repository at the tag, with `atc`
  an editable install of its `adapters/python`. The Owner installs it with
  the new `atc install TAG [--check] [--json]`; agents run only `--check`
  (hard-deny rule `atc-install`). It no longer runs the canonical checkout's
  code, which stays the workspace `atc` reads (records, policies, governance,
  skills) and still has to be on `main` (`CHECKOUT_NOT_MAIN`). `atc-maintain`
  also refuses in a release copy.
- `atc guard --install` points the PreToolUse hook at the installed copy's
  engine, and the hook table write-protects `~/.atc/releases`; until the
  Owner reruns it after an install, the hook runs the previous copy and
  `atc guard` reports the drift.
- From a release copy, `task create|update|resume|close`, `test ID` (but
  `--clean`, `--list`, `--private`), `integrate` and `push`, `--check`
  included, stop with `STOP RELEASE_MISMATCH` on a registered project whose
  `.atc/atc.lock` does not pin the installed release; the hint names
  `atc sync <project>` for a pin behind it or missing, and the Owner's
  `atc install` of the pinned tag for a pin ahead of it. The workspace root
  is never compared, and `uv run atc` in a topic worktree compares nothing.
- From a release copy, `atc sync` with no `--revision` renders the installed
  release's commit, not the latest tag; an installed release not on `main`
  stops it with `RELEASE_NOT_ON_MAIN`. With no release installed it keeps the
  latest tag.
- `atc doctor` reports the installed version and the copy it runs from (WARN
  while `atc` still runs the canonical checkout), each project's pin against
  the installed release, and ERROR for a release copy with tracked
  modifications or a HEAD that is not its tag's commit.
- `atc test ID --mutants FILE` stops with `STOP MUTANTS_INVALID` and a hint
  showing the shape when the file is unreadable, not JSON or wrongly shaped,
  before any export or scratch; the atc-testkit runner refuses the same file
  with exit 9. An empty mutant list is invalid.
- `atc init`'s PATH hint names `uv run --directory <root>/adapters/python
  atc install <latest tag>` (was `uv tool install -e`).

Commands removed or renamed (ATC-0046 unless named):

- `atc worktree create --owner H --topic T` → `atc task create [TITLE]
  [--scope] [--tests] [--file] [--project]`, which also writes and commits the
  record; `--session` and `--base-sha` are gone.
- `atc worktree resume` → `atc task resume ID` (`--session`,
  `--rebind-session` gone); `atc worktree audit` → `atc task list -v`;
  `atc worktree clean` → `atc task close ID [--abandon]` (`--archive-tag`,
  `--expected-head`, `--squash-integrated`, `--reviewed`, `--expected-main`,
  `--integrated-as` and `--retained-ref` gone: a recorded squash closes with
  no flag, § Explicitly authorized squash).
- `atc task new --scope [--version]` → `atc task create`; `--version` is gone.
- `atc task plan|start|rank|drop` and the backlog branch are removed: a task
  gets its ID from `atc task create`, allocated from `main`, branches, archive
  tags and the integration ledger. `atc task list --status planned` is gone.
- `atc task check` → `atc-maintain task check`.
- `atc close-out --task ID [--project] [--skip ITEM] [--check]` →
  `atc task close ID [--check]`; `--skip` and `--project` are gone (the
  record's `keep` stays).
- `atc verify --reviewed --rebased --task --project --verify-timeout` →
  `atc test ID --candidate [--sha SHA]`; its last line is
  `PASS candidate <sha> FF|NO_FF` (was `VERIFY PASS <candidate> <FF|NO_FF>`).
- `atc integrate --task ID --reviewed SHA [--rebased SHA] [--project]
  [--owner-run | --owner-words QUOTE] [--verify-timeout]` →
  `atc integrate ID [--sha SHA] [--check]`. The reviewed SHA defaults to the
  newest PASS review report `~/.atc/reports/<ID>-<sha>-review.md`; commits
  after it stop with `UNREVIEWED_COMMITS`; a rebased branch is found by
  patch-id with no `--rebased`; the declared verifier timeout has no override.
- `atc preflight push` → `atc push NAME... | --all [--check]`, the Owner's;
  bare `atc push` checks every repository and pushes nothing.
- `atc test run --scratch --tree --python --task --select --label --timeout
  --progress --wide --touched` → `atc test ID [--sha SHA] [--all] [-v]
  [-- PYTEST_ARG...]`: the related tests since the record's `base_sha` in the
  task's worktree, or with `--sha` in the scratch `<ID>-<sha7>`; `--timeout`
  moves to `timeout` under `[tool.atc-testkit]`; `SKIPPED_WIDE` and
  `select_full_fraction` are gone.
- `atc test mutants --python --tests --kill-rule NAME SHA DIR FILE` →
  `atc test ID --mutants FILE [--sha SHA] [-- TEST...]`; the kill rule is a
  mutant's `kill_rule` key; a surviving mutant exits 1 (was 0).
- `atc test status` → `atc doctor -v`; `atc test private` →
  `atc test --private -- COMMAND`.
- `atc tmp checkout` → `atc test ID --sha SHA`; `atc tmp list` →
  `atc test --list [ID]`; `atc tmp clean` → `atc test ID --clean`;
  `atc tmp prune` runs on every `atc test`. `python -m atc_testkit.commands`
  is gone.
- `atc onboard (--check | --sync) (--project NAME | --all | --root-only)
  [--prune] [--verbose]` → `atc sync [NAME...] [--check] [--revision SHA]
  [-v]`: bare `atc sync` covers every project, it writes and commits by
  default, prunes orphaned managed adapters on every run, and
  `--revision` takes 7 or more hex characters (ATC-0043, ATC-0046).
  `--root-only` → `atc-maintain sync --root`.
- `atc validate` → `atc-maintain validate`; `--projects` → `atc sync --check`.
- `atc bootstrap init` → `atc init`; `atc bootstrap add --project NAME` →
  `atc add NAME`; `atc bootstrap status` is removed (`atc doctor`,
  `atc sync --check`).
- `atc enforce` → `atc-maintain guard` (the generator with `--out`,
  `--live-*`, `--local-out`, `--hook-out`); `atc enforce --install-hooks` →
  `atc guard --install`, and bare `atc guard` checks the installed hook.
- `atc policies check` → `atc-maintain policies check`; its success line is
  `OK <kinds>` (was `ok: <kinds>`), the policy kinds it loaded.
- `atc classify` and `atc friction` are removed, with `classify_change.py`,
  `check_workspace.py` and the `classify-change` conformance cases.
- `atc-maintain` runs only as `uv run --locked atc-maintain` in an ATC
  worktree; it is not part of the installed `atc` and refuses the canonical
  checkout.

Output, records and configuration:

- Output rule (`shared/conformance/CLI.md` § Output): a success prints one
  verdict line with no next-step line; `-v` adds detail. A `STOP` or `ERROR`
  line is followed by `hint: <fix>`, replacing the `next:` lines; `--json`
  carries `hint` in place of `next`. An argument error no longer prints a
  `next: atc ... --help` line. `atc integrate --check` no longer reports
  `authority=missing`, and its `reuse` names the `atc test ID --candidate`
  record (ATC-0046).
- Task records: `branch`, `base_sha` and `governance_revision` are required;
  `title` and `tests` are new; `closure`, `rank`, `after`, `notes` and
  `version` leave the schema. Status `planned` is gone; `closed` is derived
  from the integration and the branch being gone, `abandoned` from the tag
  `archive/<ID>` (ATC-0046).
- Test levels: `tests: none|standard|strict`, default `standard`; `none`
  needs an Owner decision line in the record, and a project without
  atc-testkit has only `none` (ATC-0046).
- Worktree and branch names are `<harness>+<ID>` with the lock reason
  `<harness>:<ID>` (were `<owner>+<topic>`, `worktree-<owner>+<topic>` and
  `<owner>:<topic>:<session>`); the harness comes from the session's
  environment, else `HARNESS_UNKNOWN` (ATC-0046).
- `workspace.yaml` takes a top-level `skill_harnesses` map (project →
  `claude`, `codex`, `dsh` or `all`; default all), and `atc sync` renders a
  complete skill copy into every selected harness directory, `.dsh/skills/`
  included for every skill, and deletes copies in unselected ones. A project
  with no `AGENTS.md` gets a minimal one (ATC-0043, ATC-0046).
- Every scratch under the ATC temporary root belongs to a task and is named
  `<ID>` or `<ID>-<sha7>`; `atc task close` lists task-named scratches not
  registered to the task for the Owner's consent and never deletes them
  (ATC-0044, ATC-0046).

Skills:

- `atc-worktree` machine contract 2: task-ID identity and harness naming,
  driven through `atc task`; the `atc worktree` commands, the owner token and
  the session id are gone (ATC-0046).
- `atc-coordinator` and `atc-review` name the new commands: a PASS ends with
  `atc integrate <task> --sha <sha>`, the reviewer runs what the test level
  names, close-out is `atc task close`, publication is `atc push`
  (ATC-0046).

Governance:

- `GIT_WORKFLOW.md` § Task and authority, § Integrate: the Owner runs every
  integration and running it is the authority; a record granting
  `integrate_main` no longer lets an agent integrate, and `--owner-run`,
  `--owner-words` and the `record` authority kind of new ledger lines are
  gone (readers still accept existing lines) (ATC-0046).
- `GIT_WORKFLOW.md` § Publication boundary, § Owner-run commands and
  `DELIVERY.md`: the Owner pushes with `atc push <project>`, which refuses a
  commit no integration or sync recorded; agents run only `--check` (ATC-0046).
- `GIT_WORKFLOW.md` § Explicitly authorized squash: the coordinator records a
  squash as a `kind: squash` ledger line, and `atc task close` closes it as
  integrated, keeping `archive/<ID>` (ATC-0046).
- `GIT_WORKFLOW.md`: `create --base-sha` takeover of a published topic is
  removed; § Governance sync commits names `atc sync` and
  `atc-maintain sync --root` (ATC-0044, ATC-0046).
- `VERIFICATION.md` § Test levels is new, and § Independent review runs what
  the task's level names, with `atc test <task> --candidate` in place of
  `atc verify` (ATC-0046).
- `shared/conformance/CLI.md` § Versions and compatibility: a removed or
  renamed command or option keeps no alias for one minor version; the
  deprecation rule and § Deprecated forms are gone (ATC-0046).

Policy:

- `policies/hard-deny.yaml`: agents run `atc integrate`, `atc push` and
  `atc remove` only with `--check` or `--help`; `atc guard --install` and
  `atc-maintain guard --hook-out` are the Owner's; every `atc test` form runs
  in the foreground. The `atc-integrate-owner-voice`, `atc-verify-background`,
  `atc-test-run-background` and `atc-enforce-hook-install` entries are
  replaced (ATC-0046).
- The PreToolUse hook refuses a write target it cannot resolve statically:
  PowerShell redirections, `Out-File`, `Set-Content`/`Add-Content`,
  `Tee-Object`, `New-Item`, `Copy-Item`/`Move-Item` and `[IO.File]::Write*`
  through variables or environment variables it cannot follow, and the shell's
  equivalents; a payload it cannot parse is refused (ATC-0045).

## Tasks

- ATC-0042: the pre-push gate accepts a tag push whose commit is already on a
  remote-tracking ref; a test run's timeout ends its whole process tree before
  it returns; a review file's first line is its verdict token, which
  close-out reads.
- ATC-0043: `atc sync` replaces `atc onboard`, with per-project skill
  harnesses, prune by default and a minimal `AGENTS.md` for a project with
  none.
- ATC-0044: every scratch belongs to a task; close-out lists unregistered
  task-named scratches for consent; mutants run in the scratch copy's own
  environment; every written form of a CONDITIONAL PASS reads as one; a
  scratch is registered before it is created.
- ATC-0045: the PreToolUse hook checks every PowerShell and shell write
  target, models line continuations, glued options, `git -C` writes and link
  targets, and reads its payload as UTF-8.
- ATC-0046: the CLI redesign: task-ID worktrees, `atc task
  create|update|list|resume|close`, `atc test ID` forms, `atc integrate ID`,
  `atc push`, `atc sync`, `atc init|add|remove`, `atc guard`, `atc-maintain`,
  the output rule, test levels, and the governance, skills, docs and
  conformance that name them.
- ATC-0048: `atc install TAG` installs the host's `atc` and hook from a
  release copy; the task flow stops on a project pinned to another release;
  `atc doctor` reports the install, each project's pin and the copy's
  integrity; `--mutants` validates its file.

## Upgrade

The Owner's steps on each host:

1. Leave no task worktree in any project: finish or close each with
   `atc task close ID`, which finds an old-style `<harness>+<topic>` worktree
   from the task record's `branch` (`--abandon` for a task that was not
   integrated).
2. On a host that did not create `v0.6.0`, fetch the tags into the ATC
   checkout first (`git fetch --tags`).
3. From the Owner's own terminal, one command per line:

   ```text
   atc install v0.6.0 --check
   atc install v0.6.0
   atc guard --install
   atc sync --check
   atc sync
   atc doctor
   ```

   If `atc install` reports `INSTALL_FAILED`, run from a terminal where no
   `atc` runs
   `uv tool install -e "<home>/.atc/releases/v0.6.0/adapters/python" --force`;
   `atc install v0.6.0 --check` then prints `CURRENT`.
4. Codex asks the Owner to trust the new hook entry once in `/hooks`.
5. Replace removed commands in project scripts, CI and integration verifier
   argv files with their replacements above.
