atc 0.8.0 (atc-testkit 0.15.0)

atc 0.8.0 is installed with `uv tool install` from its tag, as
`docs/WORKFLOW.md` § Installing a release states. Each line of the integration
ledger names the commits it brought onto `main` (`commits`), and `atc push`
counts a commit as recorded when a line names it, also after the Owner reset
`main` below that line's candidate. Verification runs in three layers: a lint
stage, behaviour tests, and mutants under `strict`. The lint stage is the
repository's `.pre-commit-config.yaml` run through pre-commit. `atc test ID`
runs it before its tests, `atc test ID --lint` runs it alone, and the
integration verifier runs it as the `LINT_FAILED` row. A repository adopts
the lint stage by holding that file; without it, each of them prints
`LINT_NOT_CONFIGURED` and goes on. `atc sync` ships the shared lint rules to
a project's `.atc/lint/`. Evidence is keyed by a run's
inputs, the commit's files less the paths its verifier classifies as no
check's input. A passed test file is recorded against those inputs, and the
verifier, the pre-push gate, `atc integrate` and the mutant baseline take a
run on the same inputs in place of running again. Each mutant runs its tests
fastest first on workers of the grant the command holds to its end. Removed
and renamed names keep no alias: the old spelling is a usage error.

## Breaking

The integration ledger and `atc push` (ATC-0057):

- **Record field.** Each integration line of
  `<git common dir>/atc/integrations.jsonl` that has a `main_before` carries
  `commits`: every SHA of `main_before..candidate_sha`, oldest first. A
  recovery line (`main_before` `null`) has none. A sync line carries
  `[<sync commit>]`, and an Owner-authorized squash line carries the one
  squash commit.
- **New line kind.** The ledger holds supplement lines
  `{"kind": "commits", "of", "main_before", "commits", "recorded_at"}`. They
  carry no `candidate_sha`, `records_only` or `authority`, like the `report`
  lines close-out writes. A reader that took every line for an integration
  line skips the lines without `candidate_sha`.
- **Backfill.** `atc integrate` (not `--check`) appends a supplement line for
  each older line without `commits`, while both of that line's commits still
  exist, in the same append as its own line. Recovery does the same. Its
  `--json` carries `ledger_backfill: {"added", "unresolvable"}`, and its text
  output adds `ledger: backfilled N lines` when `added` is above 0.
- **Push rule.** `atc push` and `atc push --check` take a line's commits from
  its `commits`, else from its supplement line, else from
  `main_before..candidate` computed from Git while both commits exist. This
  holds whether or not the candidate is still on `main`. A line without
  `main_before` counts only while its candidate is in `origin/main..main`, as
  before. A line whose commits can no longer be listed records none, and a
  push that carries one of them refuses with `UNRECORDED_COMMITS`.
- **Output.** The push listing marks a group whose candidate is not on `main`
  as `candidate off main`. The listing's entries in `atc integrate --json`
  add `candidate_on_main` and `recorded_by` (`line`, `backfill`, `graph` or
  `null`). The `atc push --json` rows keep their shape.

The lint stage (ATC-0058):

- **`atc test ID`.** It runs the lint stage over the files changed since the
  record's `base_sha` and the untracked ones before any test, `--all`
  included. A failure prints pre-commit's last lines, then
  `STOP LINT_FAILED: pre-commit exited <code> on <n> files; log <path>`,
  exits 1 and runs no test. A pass prints `LINT PASS <n> files; log <path>`,
  and a run with no existing changed file prints `LINT no changed file`. The
  run uses `python -m pre_commit` with the project's interpreter.
- **Adoption.** A repository whose root holds no `.pre-commit-config.yaml`
  has not adopted the lint stage. `atc test ID`, `--lint`, `--sha` and the
  verifier print `LINT_NOT_CONFIGURED: no .pre-commit-config.yaml at <root>;
  the lint stage is not adopted and does not run` and go on, and the tests
  run. With the config, a stage that cannot run, pre-commit missing from the
  environment or a hook environment that fails to build, is `LINT_FAILED`.
  `atc test ID --lint` exits 0 on `LINT_NOT_CONFIGURED`.
- **`atc test ID --lint [--sha SHA]`** is new and runs the lint stage alone.
  `--clean`, `--candidate` and `--lint` take no tests and no `--all`.
- **Consumer verifier rows (testkit 0.15.0).** The `git diff --check` row
  (`DIFF_CHECK_FAILED`), the ruff row (`RUFF_CHECK_FAILED`) and the
  documentation check (`DOCUMENTATION_REFERENCE_FAILED`) give way to one
  `LINT_FAILED` row. That row runs
  `pre-commit run --from-ref <ATC_EXPECTED_MAIN_SHA> --to-ref <ATC_INTEGRATION_SHA>`
  after the lock check, when the candidate holds `.pre-commit-config.yaml`. A documentation-only range ends after it.
- **Workspace root's verifier.** Its static checks `WORKSPACE_VALIDATION_FAILED`
  (`atc-maintain validate`) and `POLICY_CHECK_FAILED` (`atc-maintain policies
  check`) become `local` hooks of the root's `.pre-commit-config.yaml`, which
  the verifier runs as `LINT_FAILED`. The `python-adapter` job of
  `.github/workflows/validate.yml` runs the same list over every file in
  place of those two steps.
- **atc-testkit API (0.15.0).**
  - `docs.DOCUMENTATION_CHECK`, `docs.TOKEN`, `docs.documentation_problems`,
    `docs.markdown_to_check` and `python -m atc_testkit.docs --range` are
    removed. `python -m atc_testkit.docs --tracked` checks every tracked
    Markdown file as a lint hook.
  - `Project.documentation_check`, `Project.lint_scope` and
    `Project.lint_paths` are removed.
  - The `[tool.atc-testkit]` key `lint_scope` is removed from the 0.15.0
    contract, and `atc_testkit.check` reports it as no key in a project that
    vendors 0.15.0 or later.
  - `atc_testkit.check` requires `pre-commit` in the development
    dependencies of a repository that vendors 0.15.0 or later and holds
    `.pre-commit-config.yaml`, or the verifier stops with
    `TESTKIT_CONTRACT_FAILED`. A repository without the config needs no
    pre-commit.
  - `atc_testkit.check` judges a project by the contract of the testkit it
    vendors, the `version` of `vendor/atc-testkit.json`. The installed
    `atc` uses it in `atc sync`, `atc sync --check` and `atc doctor`, so a
    project on an older testkit keeps `lint_scope` and its other keys until
    it upgrades. A record that is unreadable, lacks `version` or holds a
    version that is not `MAJOR.MINOR.PATCH` is
    `testkit contract unavailable: <error>`, which refuses the project.
- **Tests moved to the lint stage.** Tests that read the repository's text
  and asserted its content give way to lint rules:
  - the basetemp, `sys.path`, packaged-schema, README-version and `rmtree`
    checks become ast-grep, drift and ruff rules;
  - `atc-maintain validate`'s text rules on shipped files become pygrep
    hooks of the root's lint stage: no environment variable naming this
    checkout, no `~/Hami` path, no hard-coded governance source.

  `atc-maintain validate` also checks the root's `AGENTS.md`
  § Integration verification as it checks a project's.
- **Hook environments.** pre-commit keeps them in `PRE_COMMIT_HOME`, which
  `atc test` and the verifier set to `~/.atc/cache/pre-commit`
  (`docs/ATC_HOME.md` § Cache).

Evidence keyed by inputs (ATC-0058):

- **Formats.** The verification report is `atc-verification-report/3`. It
  adds `inputs: {"ran_on", "digest", "excluded"}`, the run's input set
  (`shared/conformance/verification-evidence/README.md` § Input set). The
  evidence record is `atc-verification-evidence/3`, where `candidate_sha` and
  `tree` stay for audit. A reused record's `reused` adds
  `reused_from: {"ran_on", "inputs"}`. A reader no longer reuses an
  evidence record `/1` or `/2`, nor a report `/1` or `/2`, which has no
  `inputs`. `atc integrate` still wraps a `/1` and `/2` report, and that
  record is never reused.
- **Pre-push gate (testkit 0.15.0).** The gate reads the record of the pushed
  commit, else the newest valid record whose run had the pushed commit's
  inputs. The rows `COMMIT_MISMATCH` and `TREE_MISMATCH` give way to
  `INPUTS_MISMATCH`. Its `REUSE` line names `reused_from ran_on <sha>`. The
  gate's static checks still run.
- **`atc integrate` reuse.** `atc integrate` takes its own candidate record,
  else the newest passed `verify` record that ran on the candidate tree
  itself. The row `BASE_MISMATCH` (expected main, reviewed SHA, carried-over
  source) is removed, and `INPUTS_MISMATCH` comes before `TREE_MISMATCH`.
  `expected_main` and `reviewed` stay in the record for audit. A candidate
  that differs only outside the input set runs the verifier, whose test
  stages reuse each file by its inputs.
- **Input records.** These are new. A passed test file is recorded under
  `<git common dir>/atc/verification-evidence/inputs/` as
  `atc-input-evidence/1`, kept 14 days (`docs/TESTKIT.md` § Input evidence).
  The verifier runs only the files no record covers and prints
  `<stage>: REUSED <n> files, RUN <m> files`. A stage whose every file is
  covered does not start pytest.
- **`atc test ID` records evidence.** After a related run, or `--all` without
  pytest arguments, on a tree equal to its commit, `atc test ID` asks the
  tree's own verifier for the input set (`ATC_INPUTS_OF=<commit>`). It then
  prints `EVIDENCE <n> test files recorded for <sha12> (inputs <digest12>)`
  or `NOTE input evidence: not recorded: <reason>`. A verifier on an older
  testkit does not answer `ATC_INPUTS_OF`, so it records nothing.

Mutants (ATC-0058):

- **Workers.** The mutants command takes the default worker count and holds
  the grant to its end, where 0.7.0 shrank it to one token after the
  baseline. Each mutant runs with `-n W --dist loadgroup -x`, where `W` is one
  worker per 8 node IDs up to the grant. A `W` of 1 runs in process.
- **Test order.** A mutant's tests run with its own named node IDs first,
  then the others fastest first by the baseline's recorded times.
- **Baseline key.** `baseline.json` records the export's input set
  (`inputs`), and a later run reuses it when its commit has those inputs.
  A scratch with no matching record of its own takes the newest matching
  record of another scratch registered to the task, and prints
  `BASELINE-OK reused from <scratch> ...`. A record that differs prints
  `NOTE baseline: not reused: <field>` first.
- **Line recorder.** It names a test by its collected node ID, without the
  `@<group>` suffix xdist's `loadgroup` adds. Under `-n 2`, a mutant whose
  test carries an `xdist_group` was reported `INCONCLUSIVE`; it is now
  `KILLED`.

Skills and governance:

- **`VERIFICATION.md`** (ATC-0058):
  - § Testing: verification runs in three layers, lint stage, behaviour
    tests and mutants, and a lint failure stops the run. A rule about a
    file's text or structure belongs to the lint stage.
  - Test levels: under `standard` the reviewer runs
    `atc test <task> --lint --sha <sha>`; under `strict` each guard the writer
    lists names the test node ID expected to kill its mutant, and a guard with
    no such test is a test gap.
  - § Independent review: a review runs lint, reading, mutants, then the
    candidate. A lint failure or a FAIL-level finding from reading is a FAIL
    with nothing run after it, and the candidate reuses each test file's
    evidence of a clean run on the same inputs.
  - § Full regression timing and evidence reuse: reuse requires the same
    check identity and the same input digest.
  - § Verification semantics: invariant 3 says a result reused by input
    digest also names the revision it ran on, and delivery verification may
    reuse a run whose recorded inputs equal the delivered revision's.
- **`GIT_WORKFLOW.md`** (ATC-0057, ATC-0058):
  - § Integrate lists `commits` among the line's keys, says a commit is
    recorded when a line's `commits` names it, and adds the append-only
    supplement rule. Its reuse paragraph requires a passing record that ran
    on the candidate tree itself with the same input digest.
  - § Explicitly authorized squash writes `commits`.
  - § Test evidence allows a run whose recorded inputs equal the integration
    revision's.
  - § Task and authority scopes its key list to integration lines and names
    supplement and report lines.
- **`CORE.md`:** whitespace only, a blank line after the capability fence
  (ATC-0058).
- **`atc-review`** (ATC-0058): reviewer step 2 is
  `atc test <task> --lint --sha <sha>`, where `LINT_FAILED` is a FAIL with
  nothing read or run after it. The steps run lint, reading, then execution,
  and under `strict` the mutants run before the candidate. The `strict` step
  report lists each guard as `file:line` → what it blocks → the expected
  killing test node ID. The skill's contract is unchanged.

## First run of the lint stage

The first lint run on a host builds pre-commit's hook environments in
`~/.atc/cache/pre-commit`. Vale is the `vale` hook of `vale-cli/vale` at
`v3.27.0` with `language: golang`. pre-commit downloads Go 1.27.4 (its
`language_version`) and Vale's modules and builds the binary, so the host
needs no Go of its own. `docs/TESTKIT.md` § Lint stage records about
35 seconds and 300 MB in the hook cache on the workspace's Windows host.
Later runs reuse the environment, and a new `rev` or `language_version`
builds again. The build reports `vale version master`, and the `rev` is the
version. The other hooks' environments, including markdownlint-cli2's, are
built on the same first run. `docs/TESTKIT.md` records no figure for them.

until it upgrades. `atc test` runs from the atc-testkit that installs with
`atc`; the project's verifier and pre-push gate run from its vendored one.

A project that upgrades follows `adapters/python/atc-testkit/README.md`. It
builds the wheel from the tag, commits it under `vendor/`, pins
`atc-testkit==0.15.0`, and adopts the lint stage or not (row above). In the
same change it removes `lint_scope` from `[tool.atc-testkit]`, since the
0.15.0 contract refuses it; until then the project keeps the key, which its
older verifier's ruff row reads.

`min_atc` in `atc-manifest.yaml` is 0.8.0. atc 0.7.0 accepts verification
reports `/1` and `/2` only. Testkit 0.15.0's verifier writes `/3`, which
0.7.0 reads as `INVALID_REPORT`, so it writes no evidence record. atc 0.8.0
reads `/1` to `/3` and writes records `/3`.

## Upgrade

The Owner's steps on each host, in this order:

1. Leave no task worktree open in any project (`atc task close ID`), and run
   no session while uv replaces `atc.exe`. On Windows, rerun the install
   after a `WinError 32`.
2. On a host that did not create `v0.8.0`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host installs
   from GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.8.0#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.8.0#subdirectory=adapters/python"
   ```

4. From the Owner's own terminal, one command per line:

   ```text
   atc sync --check
   atc sync
   atc doctor
   ```

   The hook table is unchanged since 0.7.0, so `atc guard --install` is not
   rerun. `atc doctor` reports `atc 0.8.0` at `v0.8.0` with its commit, and
   exits 0 once every check is READY, WARN or NOT_INITIALIZED.
5. Replace removed names in project scripts, CI and verifiers:
   - `python -m atc_testkit.docs --range` becomes the lint stage's link
     hook;
   - `docs.DOCUMENTATION_CHECK` is removed, and `lint_scope` leaves a
     project's `[tool.atc-testkit]` when it upgrades to atc-testkit 0.15.0;
   - a script that matched `DIFF_CHECK_FAILED`, `RUFF_CHECK_FAILED`,
     `DOCUMENTATION_REFERENCE_FAILED`, `WORKSPACE_VALIDATION_FAILED` or
     `POLICY_CHECK_FAILED` matches `LINT_FAILED`;
   - a reader of `integrations.jsonl` skips lines without `candidate_sha`.

### The push after install

Root `main` has not been pushed since v0.6.0. Its push, with the tags v0.7.0
and v0.8.0, waits on this release. `main` holds c0cd5f6, which the ATC-0049
integration onto c1de26a (candidate a785fb1) brought in. The Owner then reset
`main` to c0cd5f6, so a785fb1 is no longer on `main`. atc 0.7.0 refuses
c0cd5f6 with `UNRECORDED_COMMITS`. On the ATC checkout host, after step 4:

1. Check the push. atc 0.8.0 lists a785fb1's line's commits from Git, since
   neither that line nor any supplement records them. That assigns c0cd5f6
   to the line, marked `candidate off main`, so no further integration is
   needed:

   ```text
   atc push root --check
   ```

2. Push `main`, then the two tags:

   ```text
   atc push root
   git push origin v0.7.0
   git push origin v0.8.0
   ```

The push must happen before a785fb1's reflog entry expires, which happens
about 12-15 under `gc.reflogExpireUnreachable`'s 30-day default. After a gc,
a785fb1's line can no longer be listed, and c0cd5f6 refuses with
`UNRECORDED_COMMITS`. The durable `commits` backfill of the older ledger
lines comes with the first `atc integrate` run under 0.8.0, any task's. This
release's own integration runs on the installed 0.7.0 and writes neither
`commits` nor a backfill.

### Projects

Re-sync on 0.8.0 (`atc sync <project>`, or `atc sync` for all). Until a
project's `.atc/atc.lock` pins v0.8.0, the task flow stops there with
`STOP RELEASE_MISMATCH`. The re-sync adds `.atc/lint/` and does not adopt
the lint stage: a project without `.pre-commit-config.yaml` keeps running
`atc test ID` and its verifier with `LINT_NOT_CONFIGURED`. `atc sync` and
`atc doctor` judge each project by the contract of the testkit it vendors,
so a project on an older testkit re-syncs with its `[tool.atc-testkit]`
keys as they are, `lint_scope` included. A project that upgrades to
atc-testkit 0.15.0 removes `lint_scope` in that change
(§ atc-testkit 0.15.0).

Adopting the lint stage is optional and goes through Hami-Coordinator, as
does upgrading a project's vendored atc-testkit. Hami-Coordinator adopts it
in a task of that project:

1. In one commit, copy `shared/templates/pre-commit-config.yaml` from the
   ATC checkout to the project's `.pre-commit-config.yaml`, and add
   `pre-commit` to its development dependencies with its `uv.lock`. From
   then on the project owns that file.
2. Extend the shared rules: `extend = ".atc/lint/ruff.toml"` in the
   project's ruff settings, and
   `"config": {"extends": ".atc/lint/markdownlint.jsonc"}` in its
   `.markdownlint-cli2.jsonc`.
3. Run `atc test ID --lint` and fix the findings. The first run on a host
   builds the hook environments (§ First run of the lint stage).
4. For the verifier's `LINT_FAILED` row, vendor atc-testkit 0.15.0
   (§ atc-testkit 0.15.0).

## Assets

Verify the downloads with `sha256sum -c SHA256SUMS`.
