atc 0.11.0 (atc-testkit 0.17.0)

atc 0.11.0 gives a project task one command for its enforcement files:
`atc policy render ID` renders `policies/hard-deny.yaml` into
`generated/enforcement/` and updates the copies the project keeps
(`.claude/settings.json` `permissions.deny`, `scripts/git-hooks/pre-commit`).
A project policy can name paths under its own state root as `${state}/...`,
which the PreToolUse hook resolves from `workspace.yaml` and enforces. The
hook now also checks Claude Code's `Read`, `Grep` and `Glob` against every
filesystem rule that denies `read`, in every session. The machine-local
`.claude/settings.local.json` segment is gone: the hook's state-root deny
covers it. A carried-over integration's command now names the reviewed SHA.

## Breaking

The PreToolUse hook checks reads (ATC-0078):

- **Hook entry.** The Claude Code matcher is
  `Bash|PowerShell|Edit|Write|NotebookEdit|Read|Grep|Glob`. An entry
  installed by an earlier release is outdated: `atc guard` stops with
  `ENTRY_OUTDATED`, `atc doctor` reports `pretooluse entries` as ERROR
  `ENTRY_OUTDATED`, and `atc sync --check` prints
  `pretooluse hook ENTRY_OUTDATED`, each with the hint
  `the Owner runs atc guard --install from their own terminal`. Until it is
  reinstalled reads are not checked; writes are checked as before.
- **New refusals.** A `Read` of a path, a `Grep` or `Glob` whose `path` is
  one, or a `Glob` whose absolute or `path`-relative pattern starts in one,
  is refused when it matches a filesystem rule whose modes include `read`,
  such as the workspace policy's `**/.env` and `~/.ssh/**`. Before, such a
  rule held only in a project that committed it to `.claude/settings.json`.
  Reads take no write root and no protected path.

Enforcement rendering moves to `atc policy render` (ATC-0078):

- **`atc-maintain guard`.** Removed: `--policies`, `--out`, `--local-out`,
  and the `--check` comparisons `--live-claude`, `--live-claude-local`,
  `--live-codex` and `--live-hook`. A project renders its files with
  `atc policy render ID`, and `atc policy render ID --check` replaces the
  comparison of `generated/enforcement/` and the kept copies. What remains
  is `--hook-out DIR`, and `--check` with `--live-hook-table`,
  `--live-claude-hooks` or `--live-codex-hooks`, all with `--workspace`.
  `atc-maintain` is the maintainer CLI, outside `atc`'s compatibility range;
  it is listed so a script that called it finds the replacement.
- **Machine-local segment.** `atc-maintain guard --local-out` no longer
  writes the `Edit(//<state root>/**)` entries for
  `.claude/settings.local.json`, and `atc sync --check` no longer prints
  `machine-local state deny missing` or `... differs`. Entries already in a
  project's untracked `.claude/settings.local.json` stay and duplicate the
  hook's state-root deny; removing them is the Owner's choice.
- **`atc sync --check`.** A project's `.enforcement` check also fails when a
  kept copy (`.claude/settings.json` `permissions.deny`,
  `scripts/git-hooks/pre-commit`) differs from the render, and its hint is
  `run atc policy render <task ID> in a task for <project>` instead of
  `run atc-maintain guard`. It prints, without failing,
  `filesystem.deny[<i>] names ${state} but workspace.yaml gives <project> no state; the hook skips it`.
- **`unresolved-token`.** A project policy's glob that starts with
  `${state}/` is no longer refused; the token anywhere else in a glob, or in
  the workspace policy, still is.

The carried-over integration command (ATC-0076):

- **`atc-review` and `atc-coordinator` skills, `docs/WORKFLOW.md`.** After
  a rebase whose review carries over, the Owner's command names the
  reviewed SHA, not the rebased tip: `atc integrate` takes the rebased tip
  from the task's branch and records it as `reviewed`, with the reviewed
  SHA as `carried_over_from`. A command naming the rebased tip integrates
  it as a direct approval and records no `carried_over_from`.

## Upgrade

The Owner's steps on each host, in this order:

1. Run no `atc test`, verifier or other `atc` command while uv replaces `atc`: `atc doctor`
   reports its `atc environment` line READY. On Windows, rerun the install after a `WinError 32`.
2. On a host that did not create `v0.11.0`, fetch the tags into the ATC
   checkout (`git fetch --tags`).
3. Install `atc` from the tag. The ATC checkout host installs from the
   checkout (forward slashes, `%20` for a space); every other host installs
   from GitHub:

   ```text
   uv tool install --force "git+file:///<checkout>@v0.11.0#subdirectory=adapters/python"
   uv tool install --force "git+https://github.com/yulinnliu/agent-traffic-control@v0.11.0#subdirectory=adapters/python"
   ```

4. From the Owner's own terminal, one command per line:

   ```text
   atc guard --install
   atc sync --check
   atc sync
   atc doctor
   ```

   `atc guard --install` writes the hook entry with the new matcher; until
   it runs, `Read`, `Grep` and `Glob` calls are not checked. `atc sync
   --check` lists each project pinned to an older release and stops with
   `STOP DRIFT`; `atc sync` then moves each pin with the updated
   `atc-review` and `atc-coordinator` skills. `atc doctor` reports
   `atc 0.11.0` at `v0.11.0` with its commit, and exits 0 once every check is
   READY, WARN or NOT_INITIALIZED.

### Projects

Re-sync on 0.11.0 (`atc sync <project>`, or `atc sync` for all): each
project gets the updated `atc-review` and `atc-coordinator` skills and its
lock at v0.11.0; until then its task flow stops with
`STOP RELEASE_MISMATCH`. The testkit is unchanged, so a project keeps its
vendored testkit.

A project with `policies/hard-deny.yaml` changes its policy in its own task
and renders with `atc policy render <ID>` in that task's worktree, which
replaces `atc-maintain guard --policies ... --out ...` in the project's own
docs. A rule for a path under the project's state directory is written as
`${state}/<rest>`; it reaches the hook only, and takes effect when the task
is integrated, with no Owner command. A hard-coded state-path rule that such
a task replaces stays in the hook's baseline, and `atc guard` and
`atc doctor` list it as `retained`, until the Owner runs `atc guard --reset`
after integrating that task.

A project that upgrades its
vendored atc-testkit follows [Upgrading a project's testkit](../TESTKIT.md#upgrading-a-projects-testkit).
